# docs/spec/ —— L2 确认卡归档

这里放 `/spec` 产出、并经确认定稿的确认卡。规则见
[`docs/与我协作的约定.md`](../与我协作的约定.md) 第 8 条。

## 命名

```
<YYYY-MM-DD>-<主题>.md      例：2026-08-04-neupan-窄门通过率.md
```

## 用法

1. L2 请求 → `/spec` 出七栏确认卡 → 用户确认定稿
2. 定稿后落到这个目录
3. **开新会话**执行它（实现阶段上下文干净，且卡不会被上下文压缩吃掉）
4. 实现完成后回来，在文件顶部标结果

例外：改完当轮就能验完的小改动不用落盘，直接做。

## 生命周期（重要）

实现完成后**必须回来标结果**，否则这个目录会退化成一堆无人认领的旧文件。
在文件第一行加：

```markdown
> **结果**：通过 / 未通过 / 放弃 / 待复盘 —— <一句话，附对照【验收】栏的实测情况> （YYYY-MM-DD）
```

「待复盘」用于【验收】走了约定第 6 条「不可观测」出口的情况：实现已完成，
但结论要等复盘触发点到达才能下。到点后必须回来改成前三种之一。

「未通过」和「放弃」比「通过」更值得留 —— 它们记录的是走过的死路，
下次同一个地方再出问题时，先翻这里，看当时的【假设】验没验、结论是什么。
