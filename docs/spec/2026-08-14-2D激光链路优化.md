# 2D 激光链路优化：从"驱动能出点"到"能建干净的图"

> 等级：**L2**（跨包、新增滤波器、可能新增节点）。2026-08-14 定稿。
> 范围：**只动 hw 侧**（sim 后议）。
> **状态：未开工。** 阶段 A 的工具（`scripts/lidar_diag.py`）已交付并经合成数据验证，
> 但 A0/A1/A2 的实测数据一次都还没正式采到（08-14 试跑过一次，数据存 `/tmp` 随开发板重启丢失，
> 且当时脚本判据有误 —— 那次的两个副产物已并入下方【事实】F11/F12）。

## 【目标】

消除实机建图中的**墙面重影/变厚**，并把 `/scan_filtered` 的点云质量做到可交付。

用户主诉两条，根因不同，分两条线独立处理：
- **① 建图时墙重影/变厚** → 运动畸变/时延（C 阶段）
- **② 说不清，就是感觉不干净** → 滤波链 + 立柱回波（B 阶段）

## 【事实】（逐条已在源码/配置/实测中核对）

**F1. 拖尾点当前无任何处置。**
[laser_filters.yaml](../../src/my_bot_hw/config/laser_filters.yaml) 只有 range / speckle /
angular_bounds 三个滤波器，都不针对掠射角伪点。Humble 自带的 `laser_filters/ScanShadowsFilter`
专治此类，已编译在 `/opt/ros/humble/lib/liblaser_scan_filters.so`，**当前未启用**。

**F2. speckle 滤波器接近空转。**
`laser_filters.yaml:25` `max_range_difference: 0.6`；同目录
[激光过滤调参.md:71](../../src/my_bot_hw/docs/激光过滤调参.md#L71) 记的是 `0.1`，文档与实配已不一致。

**F3. 车体自遮挡过滤是空占位。**
`laser_filters.yaml:37-38` `lower_angle == upper_angle == 0.0`。

**F4. 运动畸变没补偿，但驱动已提供补偿所需的全部信息。**
[sllidar_node.cpp:212](../../src/sllidar_ros2/src/sllidar_node.cpp#L212)
`header.stamp = start`（扫描**起始**时刻），同文件 `:226-227` 正确填了 `scan_time` 与
`time_increment`。即下游用一圈**开头**的位姿代表整整 100 ms 的数据。

> ⚠ **F4 的后半句已被 A2 实测推翻（2026-08-14）**：`time_increment` 的**大小**对，
> **方向反了** —— `:243-251` 的 `reverse_data` 分支倒序写 ranges，索引递增 = 时刻递减；
> 且 `header.stamp` 比该帧第一束早约 32 ms。见【执行记录】的 A2 追加自证。
> **C1/C2 的实现前提随之作废，开工前重新出卡。**

**F5. 畸变量在导航常规动作下是 3.44°。**
[nav2_params_hw_rpp.yaml:130](../../src/my_bot_nav/config/hw/nav2_params_hw_rpp.yaml#L130)
`rotate_to_heading_angular_vel: 0.6` rad/s × 0.1 s = 0.06 rad = **3.44°**；
3 m 处对应墙面横向错位 18 cm = 3.6 个栅格（地图 resolution 0.05）。
而 `use_rotate_to_heading: true` ⇒ **每次路径转向都触发**。

**F6. costmap 未设 `inf_is_valid`。**
range filter 把超程点换成 `+inf`，而 `nav2_params_hw_rpp.yaml:189` / `:233` 的 scan 源
均未声明 `inf_is_valid`（默认 `false`）⇒ inf 束被整束丢弃，该方向**不做 raytrace 清障**。

**F7. 雷达外参只标了 yaw。**
[robot_bringup.launch.py:47](../../src/my_bot_hw/launch/robot_bringup.launch.py#L47)
`lidar_yaw:=3.115414361`（2026-08-13 对墙复标，残余 0.047°）；
`robot.urdf.xacro:7-9` 的 `lidar_x=-0.047 / y=0 / z=0.072` 是**设计值，未标定**。
雷达↔底盘的**时间延迟 τ 也从未标定**。

**F8. IMU 侧有一份已批准但未执行的 spec。**
[2026-08-07-IMU姿态解算yaw稳定性改造.md](2026-08-07-IMU姿态解算yaw稳定性改造.md)，
写明"不动 ROS 侧任何文件"，但其射程覆盖 `ekf_hw.yaml` 消费的 yaw 源质量。

**F9. 四根立柱贯穿扫描平面，URDF 里没有建模。**
[robot_core.xacro:49](../../src/my_bot/description/robot_core.xacro#L49) 只有一句
"由立柱撑开"的注释，无对应 link。雷达 `z=0.072`、第二层顶面离地 0.16 ⇒ 必然贯穿。

几何（用户 CAD 截图 + 口头更正，2026-08-14）：

| 量 | 值 | 出处 |
|---|---|---|
| 柱直径 | **6 mm**（r = 0.003 m） | 用户更正（先前口述 0.06 m 是笔误） |
| 柱心半径 `R柱` | **102.53 mm** | 截图「中心距离」，基准 = 底盘圆心 = 雷达中心 |
| 方位 | **±45° / ±135°** | 截图 `dX = dZ = 72.5 mm`，`72.5×√2 = 102.53` ✓ |

雷达在 `(-0.047, 0)` = 圆盘圆心正上方 ⇒ 遮挡半角 `asin(0.003/0.10253)` = **1.677°**，
单柱全角 3.353°，**四柱合计 13.41°**，剩余视野 346.6°。
柱外沿距盘心 105.53 mm **< 圆盘半径 110 mm，全在盘内**，Nav2 的 footprint 与裸外廓都覆盖得住。

⇒ **立柱的遮挡量微不足道，不动机械。** 但它有次生问题，见 F10。

**F10. 柱面回波距离恰好骑在 `lower_threshold` 上 —— 这才是立柱的真实危害。**
柱面最近点到雷达 `= R柱 − r = 99.53 mm`，可见弧上距离范围 **99.5 ~ 102.5 mm**。对上三个门限：

| 门限 | 值 | 柱子回波的命运 |
|---|---|---|
| `sllidar_node.cpp:228` `range_min` | 50 mm | 通过 |
| C1 物理盲区（[激光过滤调参.md:50](../../src/my_bot_hw/docs/激光过滤调参.md#L50)） | ~80 mm | 通过 —— **雷达能测到柱子** |
| `laser_filters.yaml:11` `lower_threshold` | **100 mm** | **99.5~102.5 骑在阈值两侧** |

**这是不稳定的临界配置**：一部分柱子回波会穿过 range filter 进入 `/scan_filtered`，
在 costmap 里变成**贴身假障碍**；穿过多少随装配误差、雷达是否精确在盘心、温漂而跳变。
**这大概率是主诉②「感觉不干净」的一个真实来源。**

**F11.（08-14 实测）实际角分辨率是 0.5°/束，不是 0.25°。**
`/scan` 为 **720 束/圈**（`angle_compensate` 把 C1 的 500 点/圈重采样成 720），10.02 Hz。
⇒ 立柱的 3.353° 只覆盖 **6.7 束**；且 F5 的畸变、F10 的判定都要按这个分辨率复核。
**所有"相邻点"类阈值（speckle 的 `max_range_difference`、shadow 角）都与分辨率强相关，
不能把 0.5° 下测出的分位数用到别的分辨率上。**

**F12.（08-14 实测）柱子回波是间歇的，命中率约 17%。**
柱面 99.5 mm 落在 C1 探测能力边缘，回波强度不足 ⇒ 那几束只有约 1/6 的帧测得到。
这既不是"稳定遮挡"（有效率 0）也不是"稳定回波"（有效率 1）。
**A0 的判据必须按此设计**，否则柱子会被"有效率高"这类条件筛掉（08-14 就踩过：
按点云特征盲找柱子，捞出 8 个低反射率环境物体，真柱子反被筛没）。

## 【假设】（未验证，需先验或标明怎么验）

**H1. 用户说的"拖尾点"= 掠射角伪点（shadow points）。**
验法：A1 的 shadow 角分位数。若实际是"动态障碍在 costmap 里留的残影"，那是 F6，走 B4。

**H2. 墙重影集中发生在旋转时段，而非直线行驶。**
验法：A2/A3。若直线段也重影严重，说明还有轮速标定或 EKF 侧问题，C 阶段不足以解决。

**H3. `τ + t_eff` 是重影的主导项。**
**必须先验**，它决定 C 走哪条路（改一行时间戳 vs 新写一个节点）。验法即 A2。

**H4. CAD 的 dX/dZ 轴与车头方向对应，即四柱在 ±45°/±135° 而非 0/90/180/-90。**
这是立柱一线**唯一没有独立证据**的一环。验法即 A0 的判定 1。

## 【方案】

三阶段。**A 先跑，B/C 的具体数值由 A 的数据回填。**

### 阶段 A —— 量化测量（只读，不改任何工程文件）

工具 `src/my_bot_hw/scripts/lidar_diag.py` **已交付**（CMakeLists 已注册）。
四个子命令，均已用合成数据端到端验证（含反例）：

| 子命令 | 对应 | 产出 | 已验证 |
|---|---|---|---|
| `record` | 采集 | scan(+odom/imu) → npz | — |
| `verify` | **A0** | 按 CAD **核对**四根立柱；判定 1 = H4；判定 2 = F10 | 正例 7/6.7 束、命中率 17.2%；反例（方位错）正确报 ✗ 并指出真实方位 |
| `noise` | **A1** | 噪声本底 σ、shadow 角分位数、相邻点跳变分位数 | 合成 σ=8 mm → 测出 8.0 mm |
| `delay` | **A2/A3** | 纯传输时延 τ、`t_eff`、帧内畸变 Δθ_intra | 合成 τ=40 ms → 36.3 ms；Δθ=3.44° → 3.19° |

> **A0 是核对不是检测**：立柱位置由 CAD 算出（F9），脚本只回答"这四个位置上实测到了什么"。
> 08-14 试过靠点云特征盲找，在真实环境里失败（F12）。尺寸已知就不该盲找 ——
> 核对还有个额外好处：**能被证伪**，方位不对时会直接报错，而检测只会"找到什么算什么"。

**采集要求：**

| | A0 + A1（一份数据两用） | A2 |
|---|---|---|
| 车 | **全程静止 60 s** | 原地**往复摆动 ±15°、\|ω\|≈0.6 rad/s、45 s** |
| 位置 | 四周 1.5 m 内无物体，但视野里要有墙角/门框/桌腿（A1 要边缘才测得出 shadow 角） | 正对直墙 1.0~1.5 m，墙需覆盖 ±35° |
| 其他 | **不许有人在雷达平面（离地 7 cm）内走动** —— 会造成假的近点与 shadow 污染 | 同左 |
| 命令 | `record --duration 60 --out ~/a0.npz` | `record --duration 45 --with-odom --out ~/a2.npz` |

> ⚠ **输出别放 `/tmp`** —— 开发板的 `/tmp` 是 tmpfs，重启即失（08-14 丢过一次）。
> ⚠ **A2 必须是往复摆动不是整圈旋转**：0.6 rad/s × 20 s ≈ 两圈，前方扇区会扫过每一面墙，
> 墙面法向解缠失效（合成数据上算出 τ=616 ms 的离谱值）。脚本已内置守卫：
> 帧间法向跳变 >15° 直接拒绝出数。
> ⚠ 涉及运动的 A2 **由我给命令、用户执行**（约定 15）。A0/A1 静止采集可代跑。

**分支判据（写死，执行时不再讨论）：**

*A0（判定 1，对应 H4）：*
- 四个方位全部核对到 → H4 确认，不动机械，继续 B
- 一个都没核对到 → 改用 `--expect 0,90,180,-90` 重跑；仍为 0 则 F9 需重查。
  若确为 0/90/180/-90（正前正后被挡）→ **单独出卡评估「雷达绕 z 转 45° 重装」**
- 只中一部分 → 装配不对称或有别的遮挡，看反证栏

*A0（判定 2，对应 F10）：*
- 超过阈值的比例落在 **2%~98%** → F10 成立，执行 **B3a′ + B3a**
- ≥98% → 回波全穿过，**B3a 必做、B3a′ 不必**
- ≤2% → F10 在本机不成立，**B3a′ 不做、B3a 降级**

*A2/A3（判据量是 `τ + t_eff`，不是 τ）：*
`t_eff` = 参与拟合的束在帧内的平均采样时刻（前方扇区因 `lidar_yaw≈π` 落在帧首尾，
合成下 ≈47 ms）。**下游按 `header.stamp` 查 TF 的实际误差 = τ + t_eff**，这才是 C1 要消掉的。
- `|τ+t_eff| > 30 ms`（>0.3×scan_time）→ **时延主导**，先做 C1，改完重跑 A2
- `< 10 ms` 且 Δθ_intra 与 3.44° 吻合（±20%）→ **畸变主导**，直接上 C2
- 两者都显著 → 先 C1 再 C2，**C1 做完必须复测，不许叠着做**
- `< 10 ms` 且 `Δθ_intra < 1°` → **C 阶段无事可做**，墙重影另有来源，回查 H2
- 回归 `R² < 0.5` → τ 不可信，先查墙面拟合质量与 odom 时间戳抖动，**不要拿它做决策**
- ⚠ C2 做完复测必须加 `--deskewed`，否则会把 47 ms 的 `t_eff` 整个误算进 τ

### 阶段 B —— 滤波链与 costmap（治主诉②）

改 `src/my_bot_hw/config/laser_filters.yaml`，顺序有语义、不可换：

```
/scan
 ├ [1] LaserScanRangeFilter              去盲区/超程      【B3a′: 0.10 → 0.09】
 ├ [2] ScanShadowsFilter                 拖尾点           【B1 新增】← 必须在 speckle 之前
 ├ [3] LaserScanSpeckleFilter            孤立毛刺         【B2 收紧，阈值由 A1 定】
 ├ [4] LaserScanPolygonFilter            车体轮廓+立柱回波 【B3a 必做，替换占位的 angular_bounds】
 └ [5] AngularBoundsFilterInPlace × 4    立柱阴影         【B3b 可选，见下】
/scan_filtered
```

- **B1 ScanShadowsFilter**：拖尾点是**连成串**的，speckle 的邻域窗口判据结构性抓不到 ——
  这就是为什么 F2 就算把阈值调回 0.1 也治不了拖尾。参数按 A1 的 shadow 角 1% 分位回填。
- **B2 speckle 收紧**：按 A1 的跳变分位数取值，不再拍 0.6 或 0.1。
  **注意 F11**：该分位数与角分辨率强相关。同步修正 `docs/激光过滤调参.md`（F2）。
- **B3a′ `lower_threshold` 0.10 → 0.09**：现值恰好切在柱子回波分布中间（F10），
  穿过与否随温漂跳变。降到 0.09（仍高于 C1 物理盲区 0.08，留 10 mm 余量）让回波**稳定进入**，
  再交给 B3a 按几何精确删。**反向做法（提到 0.11 直接砍）不采纳** —— 那会连车体外的
  真实近距障碍一起砍，是用钝器解决几何问题。
- **B3a PolygonFilter**：`polygon_frame: base_link` + `invert: true`，多边形复用
  `nav2_params_hw_rpp.yaml` 注释里那份**裸外廓** 10 点多边形 + 2 cm 余量。
  车体是不规则多边形且 `base_link` 不在圆心，角度扇区法要手工标多段且外参一改就失效。
  柱子回波落在多边形内（前柱 0.080 m、后柱 0.143 m 处），一并删净。
- **B3b 四段 AngularBoundsFilterInPlace**：**可选**。柱子阴影只有 3.353° 宽，
  且阴影区内的束会直接返回柱面距离（已由 B3a 处理），B3b 只负责扇区边缘的掠射伪点。
  若 A0 反证显示边缘本就干净，**判为"无收益，不做"** 并据实记录。
  用 InPlace 变体是硬要求：非 InPlace 会改变点数组长度，破坏角度映射。
- **B4 costmap `inf_is_valid: True`**：`nav2_params_hw_rpp.yaml` 两个 scan 源各加一行（F6）。
- **B5（可选，单独 commit）**：local_costmap 的 `voxel_layer` → `ObstacleLayer`。
  纯 2D LaserScan 用 VoxelLayer + `z_voxels: 16` + `publish_voxel_map: True` 是白花 CPU。

### 阶段 C —— 畸变/时延处置（治主诉①，走哪条由 A2 定）

> ⚠ **以下两条已按 A2 实测重写（2026-08-14）**。原文写的 C1 = `+ scan_time/2`、
> C2 = 按 `time_increment` 正向算采样时刻，**两条都不对**，理由见【执行记录】的 A2 追加自证。

- **C1（时延主导，本轮执行）**：`header.stamp` 挪到这一帧**真正对应的时刻**。
  实现处 `sllidar_node.cpp` 的 `publish_scan()`（一行，且三个调用点共用）：
  ```
  header.stamp = start + scan_duration/2 + 0.0324        // 单位 s
  ```
  两个分量含义不同，不要合并成一个魔数：
  - `scan_duration/2`（~49.7 ms）= 帧中心。几何量，转速变了自动跟随。
  - `0.0324` = **scan 链相对 odom/EKF 链的固定延迟**，A2 实测（7 个索引窗线性拟合，
    截距 +134.9 ms、斜率 −142.6 µs/束 ⇒ 首个测得的束在 `stamp+32.4 ms`）。
    它是**相对量**，不能断言全在雷达侧。CPU 负载 / DDS / scan_mode 变了要用
    `lidar_diag.py delay` 重标。
  预期残差：实测全帧均值在 `stamp+83.6 ms`，本式补 82.1 ms ⇒ 剩 ~1.5 ms。
  **须记为 vendor patch** → `src/sllidar_ros2/本地修改.md`。
  ⚠ C1 **不动** `time_increment`（仍为正、方向仍是错的）。任何按它做逐点 deskew 的
  下游（laser_geometry、costmap 投影）依旧会算错 —— 那是 C2 的射程。
- **C2（畸变主导，暂不做）**：新增 deskew 节点，`/scan` → `/scan_deskewed` → filter chain。
  **⚠ 必须按倒序算每束采样时刻**：`t_i = stamp + (M−1−i) × time_increment + 常数`。
  若按 `stamp + i × time_increment`（F4 原文的写法、也是所有教科书写法），
  畸变**不会被消掉，会反向加倍**。
  C1 做完必须先复测 A2，再决定 C2 做不做 —— 卡里写死了不许叠着做。

## 【不做】

1. **不动 `ekf_hw.yaml`、不动 IMU 融合权重。** F8 那份 spec 未执行，同时动会互相污染归因。
2. **不动 `mapper_params_hw.yaml` 来"调薄墙"。** 用 `angle_variance_penalty` 之类掩盖
   几何错位，是把 bug 调进参数里。
3. **不动 sim 侧。** Gazebo `gpu_lidar` 不建模掠射伪点与材质反射（`lidar.xacro:56` 已写明），
   B 阶段的滤波器在 sim 里**验不出效果**。
