## 【事实】

### 代码事实（已逐条在源码中核对）

**F1. deltaTime 是硬编码常数。**
[`imu.c:72`](../../firmware/my_robot_stm32/Core/Src/app/imu.c#L72) `#define IMU_FUSION_DT_S 0.01f`，
[`imu.c:204`](../../firmware/my_robot_stm32/Core/Src/app/imu.c#L204) 直接传给 `FusionAhrsUpdateNoMagnetometer`。
工程内无 DWT、无自由运行计时器。yaw = `Σ ωz_i × 0.01`，其正确性依赖"每秒恰好消费 100 个样本"，
而消费率由 ICM 内部 RC 振荡器决定（TIM6 是晶振驱动的精确 100.000 Hz，`tim.c:183-186`）。
误差单边：ODR 低于 100 Hz 则 yaw 读低；高于 100 Hz 时 TIM6 每 tick 只消费 1 帧，是正确降采样，无标度误差。

**F2. 陀螺零偏只在上电冷机标定一次，之后永不更新。**
`main.c:121-123` → `imu.c:317-355` 平均 1000 点写入 `g_gyro_bias[3]`，全工程再无第二处赋值。
附带三个缺陷：注释写"5 s"实为 **10 s**（`imu.c:78`）；**无静止校验**（被碰一下则污染整个会话，无告警）；
**无超时**（`imu.c:326` 死等 `g_ready`，此时 TIM6 尚未启动，IMU 挂掉 = 整机无响应）。

**F3. `zupt.c` 写好了完整的在线零偏跟踪，编译进了 elf，全工程零调用。**
MOVING/SETTLING/STATIC 三态机、滑窗均值+方差判据、滞回、`bias_alpha=0.02` 的 EWMA 零偏跟踪、bootstrap。
`Debug/objects.list:10` 有 `zupt.o`，`grep -rn "zupt_" Core/` 除自身外零命中。**现成的对症死代码。**

**F4. 运行时的"死区"不是静止检测。**
[`imu.c:168-187`](../../firmware/my_robot_stm32/Core/Src/app/imu.c#L168)：
判据**只看 `|gz|` 单轴**，不看 accel、不看轮速 → **直线行驶时同样持续触发**；
注释写"X/Y 轴保持原值"，代码却在 176-178 / 183-185 行**把 gyro[0]/gyro[1] 一并清零**；
进入阈值 0.01 rad/s = **0.57°/s**，退出 0.86°/s。

**F5. AAF 抗混叠滤波从未配置。** 全部 8 次寄存器写都在 Bank0，`ICM_REG_BANK_SEL 0x76` 定义了但从未被写。
按手册 DS-000347 Rev 1.2 §15.3-15.5 / §16.1-16.3 的复位值反解：


|                     | 复位值             | DELT / DELTSQR / BITSHIFT | §5.2 查得 3dB BW |
| ------------------- | ------------------ | ------------------------- | ----------------- |
| 陀螺 0x0C/0x0D/0x0E | 0x0D / 0xAA / 0x80 | 13 / 170 / 8              | **585 Hz**        |
| 加速 0x03/0x04/0x05 | 0x30 / 0x40 / 0x62 | 24 / 576 / 6              | **1220 Hz**       |

UI filter（§5.3 表，ODR=100 Hz、index 3）= **44.4 Hz，1 阶**，与 `imu.c:279` 注释一致。
Nyquist = 50 Hz，故 AAF 分别超了 11.7× 与 24×。
手册位于 `docs/vendor/C1850418_姿态传感器-陀螺仪_ICM-42688-P_规格书_WJ56255.PDF`。

**F6. Fusion 参数 gain=0.01（默认 0.5）。** 但**加速度计对 yaw 无任何直接修正能力**——
`FusionAhrs.c:170` 的反馈项是 `Feedback(normalise(accel), halfGravity)`，绕重力轴的分量恒为 0。
gain 影响 yaw 的唯一路径是倾角耦合（5° 倾角约 0.4% 标度误差）。其余参数核对无误：
`magneticRejection=0` 经 `FusionAhrs.c:88` 转成 FLT_MAX 且 mag 全零被 `FusionVectorIsZero` 跳过；
`gyroscopeRange=500` 转成 490 dps 重启阈值，地面机器人够不着。

**F7.（排除项，避免误判）** 0x02 帧发全局 `g_yaw` 而非本 tick 快照 → 但 `g_yaw` 是绝对角且 ROS 侧是
`imu0_differential`，重复帧长期无损；yaw 在 ±180° 环绕 → ROS 侧转四元数正确吸收；`g_yaw` 读写同在 TIM6 ISR，无竞态。

### 实测事实（2026-08-07 台架基线，现固件未改动）

原地正反各转 5 整圈 + 静置，Live Expression 读 `yaw_gyro_accum_deg`（死区**之前**的裸积分，`imu.c:166`）。
**测试条件：电机断电、手推**（已向用户确认）—— 这一条决定了下面所有数字的适用范围，见末尾说明。

```
A₀ = 0.0721      A₁ = A₀ − 1797.706 = −1797.634
A₂ = 0.394    →  Δ⁻ = +1798.028
A₃ = 1.1      →  Δ_static = +0.706（约 60 s）
对照：带死区的 g_yaw 全程净变化 = 0.28°
```


| 量                       | 值                                                 | 说明                                 |
| ------------------------ | -------------------------------------------------- | ------------------------------------ |
| **标度误差**             | (1797.706+1798.028)/3600 = 0.99882 →**−0.118%**  | 3600° 上少读 4.27°                 |
| **零偏（转圈段）**       | (Δ⁺+Δ⁻)/2T =**0.0027 °/s**                    | 会话早期                             |
| **零偏（静置段，最热）** | 0.706/60 =**0.0118 °/s** = 0.7°/min = **42°/h** | 会话末期，4.4× 增长                 |
| **正负标度不对称**       | 0.322°，可被零偏完全解释，**无剩余不对称**        | →`GYRO_Z_SF_POS/NEG` 正负分离无依据 |

**这组数推翻了原计划的优先级排序**：原判据写的是"差 10° 以上 → F1 坐实；1800±5° → F1 不是主因"，
实测 2.13°，落在第二格。**F1 不是主因。** 且手工对胶带的对准误差（±2° → ±0.11%）与被测量同量级，
故准确表述为：**标度误差 ≲0.15%，本方法测不出确切值，但绝不是 1%。**

**该测试的两个盲区（关键，都指向"实际工况比这组数差"）**：

**盲区一 —— 死区起作用的区间被整个避开了。** 0.0118 °/s 的零偏离死区阈值 0.57°/s 差 48 倍，
所以**死区在直线行驶时同样是 ON**——此时 IMU 对外报告"没有转动"，真实的缓慢跑偏
（轮径不等、地面倾斜、地毯）完全不可观测，而 EKF 侧 `odom0` 的 vyaw 又是关的。
5 圈快转恰好全程在死区之外。

**盲区二 —— 电机断电手推，F5（振动混叠）的贡献一点没进这组数。**
所以 **0.0118 °/s 只是"电机不转时的零偏地板"**，不是行驶工况下的零偏。
按 F5 的机理（H3：落在 100 Hz 整数倍附近的振动能量折叠到 DC，变成随转速变化的零偏），
通电行驶时的实际零偏只会高于这个地板，且随 PWM 占空比变化。
**而通电行驶正是实际使用的工况** —— 这使 F5 成为"实际观感 vs 台架数据"落差的头号候选，
与 H1（死区）并列。二者由验收 A5 与 A4 分别判定，互不干扰。

### F8（2026-08-26 复审新增）：`zupt.c` 的静止判据与零偏估计构成正反馈自锁

**这是代码事实，已在 `zupt.c` 源码中逐行核对，不是推断。**

`is_window_static()` 判的是 `|gyro_mean[i] − gyro_bias[i]| > cfg.gyro_mean_thresh`，
而 `ZUPT_STATIC` 分支里 `gyro_bias` 又被 EWMA 拉向 `gyro_mean`。环是闭合的。

失效路径：机器人以 0.3 °/s 匀速缓慢转动（斜坡、地毯、单轮轻微卡滞）时 ——
陀螺方差极低（匀速无方差）、加速度平稳 —— 偏离量 0.3 < 0.57 通过判据 → 进 STATIC →
**零偏被拉向 0.3 °/s，真实转动被吸收成零偏**。污染持久：停下后要几个时间常数才退回，
期间 yaw 反向漂。

**判据阈值同时比器件噪声底松 2~4 个数量级**（按手册噪声密度、44.4 Hz 带宽反算），
这会显著放大上述失效概率：


| 阈值               | 现值   | 等效 RMS   | 器件噪声底  | 余量      |
| ------------------ | ------ | ---------- | ----------- | --------- |
| `gyro_var_thresh`  | 2.5e-5 | 0.29 °/s  | 0.019 °/s  | **15×**  |
| `accel_var_thresh` | 0.5    | 0.71 m/s² | 0.005 m/s² | **140×** |

即 0.29 °/s 的抖动、0.7 m/s² 的振动都会被判为"静止"。`zupt.c` 自己的注释写了
"实测时把静止/运动的方差打 log，按实际噪声底再调"—— **这一步从未做过**，默认值是拍的。

⚠️ 但**不要直接按手册值收紧**：真实机器人上电静止时，支架传导的振动会让 accel 方差
远高于纯器件噪声底，收太紧会永远进不了 STATIC。必须实测整定，见【执行顺序】第 0 步。

**另有两处无兜底**（同为代码事实）：

- 无零偏限幅。上述自锁一旦发生，`gyro_bias` 可被拉到任意值，无上界保护
- 若开机标定值本身有误（标定期间被碰），偏离量会永远 > 阈值 →
  **永远进不了 STATIC，ZUPT 静默失效，无任何告警**（改动 C 的静止校验可缓解，但不能根治）

### 改动 A（主刀）：接上 `zupt.c`，删掉死区 —— 对应 F4 + F2

把 `imu.c:155-187`（减零偏 + SF 修正 + 滞回死区）整段换成 `zupt.h:21-26` 注释给出的标准用法：

```c
float gyro_raw[3] = { gx*GYRO_SCALE, gy*GYRO_SCALE, gz*GYRO_SCALE };  /* 未减零偏 */
float acc_raw[3]  = { g_imu.accel[0], g_imu.accel[1], g_imu.accel[2] };
zupt_update(&g_zupt, gyro_raw, acc_raw);
zupt_apply (&g_zupt, gyro_raw, g_imu.gyro);
```

行为差异：

- **直线行驶不再触发**：`is_window_static()` 要求三轴陀螺方差 **+ 加速度方差**同时低，
  行驶振动会让 accel 方差超阈 → 保持 MOVING → 真实 `gz` 正常通过
  （⚠️ 这一条依赖"行驶方差 > 静止方差"，尚未实测，见【执行顺序】第 0 步的方差整定）
- **不再误清 X/Y**；**0.57°/s 的硬死区消失**，代之以 A-2 的小死区
- **零偏持续跟踪**：STATIC 时以 α=0.02 EWMA 追温漂（对应实测 42°/h）

> **2026-08-26 更正**：原卡此处写有"`is_window_static` 用『窗口均值 vs 当前零偏』的偏离量判定，
> 能识别匀速慢转而不误判为静止"。**这句是错的，事实恰好相反** —— 正是这个判据构成了 F8 的自锁，
> 匀速慢转会被吸收成零偏。改动 F 修的就是它。

### 改动 A-2（2026-08-26 新增）：小死区，作用于 ZUPT 输出 —— 对应 H5 的倒退风险

死区**不是**要整个删掉，删掉的是**现在这个**（判据只看单轴、误清 X/Y、作用于未减零偏的原始值 ——
这三条都是 bug，不是设计选择）。新死区放在 `zupt_apply()` **之后**，只作用于 z 轴：

```c
/* 单位 rad/s。作用对象是已减零偏的值，而非原始 gyro */
#define GZ_DB_ENTER  8.7e-4f    /* 0.05 °/s，约 3× 噪声底 RMS */
#define GZ_DB_EXIT   1.7e-3f    /* 0.10 °/s，滞回 */
```

阈值依据 —— 零偏与真实转动之间有 500 倍空隙，现有 0.57°/s 卡在了空隙中间，没有必要：


| 量                                        | 数量级          | 来源                                    |
| ----------------------------------------- | --------------- | --------------------------------------- |
| 器件噪声底（±500dps，UI filter 44.4 Hz） | ~0.019 °/s RMS | 手册噪声密度 0.0028 °/s/√Hz × √44.4 |
| 实测零偏（断电手推，会话末最热）          | **0.0118 °/s** | 本卡【事实】实测段                      |
| **新死区 `GZ_DB_ENTER`**                  | **0.05 °/s**   | 高于零偏、低于真实慢转 100 倍           |
| ~~旧死区 `GYRO_Z_DB_ENTER`~~              | ~~0.57 °/s~~   | 删除                                    |
| 机器人有意转向的最慢角速度                | **6 ~ 17 °/s** | Nav2 min rotation vel 0.1~0.3 rad/s     |

⚠️ **死区的能力有上界，别指望它兜底**：只在「零偏 < 阈值」时管用。若通电行驶时零偏因振动混叠
升到 0.05 °/s 以上（【事实】盲区二，尚未实测），死区完全不触发。它是第三道防线，
替代不了改动 B（AAF）和 ZUPT 的在线零偏跟踪。

### 改动 F（2026-08-26 新增）：修 `zupt.c` 的自锁与零偏失控 —— 对应 F8

三处改动，约 30 行。**照 VQF 的判据结构改，但不引入 VQF 代码。**

1. `zupt.h` 的 `zupt_config_t` 增字段 `float bias_clip;`（rad/s，零偏的物理上界）
2. `is_window_static()` 追加**绝对上界**判据 —— 这是打破自锁的关键，`bias_clip` 是常量，不参与反馈：
   ```c
   if (fabsf(z->gyro_mean[i]) > z->cfg.bias_clip) { return false; }
   ```
3. `ZUPT_STATIC` 分支 EWMA 更新之后，对 `gyro_bias[i]` 做 `±bias_clip` 钳位

`ZUPT_CFG_100HZ_DEFAULT` 增 `.bias_clip = 0.05f`（2.9 °/s）—— 远高于实测零偏 0.0118 °/s
（含温漂余量充足），远低于机器人最慢有意转向 6 °/s。

顺带修 `zupt.c` 里两处不准的注释（不改行为）：

- `bias_alpha=0.02` 注释写"时间常数 ≈ 50 帧"，实际是 EWMA(τ=50) 串联 MA(50) ≈ **等效 100 帧**
- `should_exit_static()` 的 accel 分支用的是窗口方差（0.5 s 滞后），退出的实际响应速度由陀螺瞬时
  判据决定，accel 那条基本不起作用 —— 注释里写明，避免后人误以为它在起作用

与标定的衔接（`zupt_t` 是公开结构体，无需改 `zupt.c`）：

```c
zupt_init(&g_zupt, &ZUPT_CFG_100HZ_DEFAULT);
zupt_set_bias(&g_zupt, g_gyro_bias);
g_zupt.bootstrapped = true;   /* 已有静态标定，不需要 bootstrap 自吸附 */
```

`g_zupt` 需可被 Live Expressions 观察（`state` / `gyro_bias[2]` / `gyro_var[2]`），验收要用。
保留 `yaw_gyro_accum_deg`（`imu.c:166`）—— 它是死区/ZUPT **之前**的裸积分探针，基线与验收都依赖它。

### 改动 B：配置 AAF 到 42 Hz —— 对应 F5

插在 `imu.c:276` 的 `PWR_MGMT0 = 0x0F` **之前**；写完必须 `icm_write_reg(0x76, 0x00)` 切回 Bank0。
（手册中**没有**"STATIC 寄存器必须在传感器关闭时写入"的明文要求，放在上电前只是稳妥做法。）

值已对照 §5.2 表逐格核实。DELT=1 → 42 Hz，是唯一压在 Nyquist 50 Hz 之下的档位：


| Bank | 寄存器                    | 字段                                            | 写入值   |
| ---- | ------------------------- | ----------------------------------------------- | -------- |
| 1    | 0x0C GYRO_CONFIG_STATIC3  | [7:6]Reserved(复位00) / [5:0]GYRO_AAF_DELT=1    | **0x01** |
| 1    | 0x0D GYRO_CONFIG_STATIC4  | [7:0]GYRO_AAF_DELTSQR[7:0]=1                    | **0x01** |
| 1    | 0x0E GYRO_CONFIG_STATIC5  | [7:4]BITSHIFT=15 / [3:0]DELTSQR[11:8]=0         | **0xF0** |
| 2    | 0x03 ACCEL_CONFIG_STATIC2 | [7]Reserved(复位0) / [6:1]DELT=1 / [0]AAF_DIS=0 | **0x02** |
| 2    | 0x04 ACCEL_CONFIG_STATIC3 | [7:0]ACCEL_AAF_DELTSQR[7:0]=1                   | **0x01** |
| 2    | 0x05 ACCEL_CONFIG_STATIC4 | [7:4]BITSHIFT=15 / [3:0]DELTSQR[11:8]=0         | **0xF0** |

- **不写 0x0B**：§15.2 复位值 0xA0，`GYRO_AAF_DIS`(bit1)=0 已使能，`GYRO_NF_DIS`(bit0)=0 陷波器默认开
  （对准陀螺驱动谐振，与本议题无关，别动）；bits[7:2] 是**非零** Reserved，碰它只有风险。
- **不需要 read-modify-write**：上表 6 个寄存器所有 Reserved 位复位值都是 0，整字节写安全。
- 写后**回读这 6 个寄存器校验**，不一致则 `g_imu_parse_error_count++`。
- 副作用：42 Hz 2 阶滤波群延迟约 7~8 ms。对 yaw **无影响**（纯延迟不改变积分总量）；
  不参与电机 PID，无控制稳定性风险。

### 改动 C：标定缩短到 2 s + 静止校验 + 超时 —— 对应 F2 的附带缺陷

- `CAL_NUM_SAMPLES` 1000 → **200**（2 s），注释同步改对
- 累计平方和算三轴方差，结束时校验 `gyro_var[i] < 2.5e-5`（沿用 `ZUPT_CFG_100HZ_DEFAULT.gyro_var_thresh`
  保持一致）且 `|‖accel‖ − 9.80665| < 0.5`；失败则丢弃重试，最多 3 次
- 每帧等待 `g_ready` 加超时（`HAL_GetTick()`，此时 SysTick 已跑）；总超时 ~10 s → 放弃标定、
  零偏置 0、置 `g_imu_health` 错误位、**正常返回**，让电机与串口活过来

精度不因缩短而变差：200 点平均把噪声降到 σ/√200 ≈ σ/14；而 STATIC 下 α=0.02 对 50 点窗口均值做 EWMA，
稳态方差 ≈ (α/(2−α))·σ²/50，等效 **σ/70** —— 比原 1000 点标定的 σ/32 还好一倍，且持续跟踪温漂。

`main.c:121` 的 `HAL_Delay(2500)` **不动**（原因不明确，不动不理解的东西）。上电到能动：12.5 s → **约 4.5 s**。

### 改动 D（已降级）：DWT 实测 deltaTime —— 对应 F1

实测标度误差仅 −0.118%，**这不再是主刀**，但 10 行代码就能确定性消掉，顺手做。

选 DWT 而非新开 TIM7：TIM1/2/4/6 已全占用（编码器×2、PWM、100 Hz 基准），新开定时器要动 `.ioc`
重新生成代码，与 CubeIDE 侧的手改冲突。**DWT 是 M4 内核自带，零 CubeMX 改动。**

```c
#define IMU_DT_NOMINAL_S 0.01f
#define IMU_DT_MIN_S     0.002f
#define IMU_DT_MAX_S     0.050f
#define CYC_TO_SEC       (1.0f / 72.0e6f)   /* SYSCLK 72 MHz，32 位，59.6 s 回绕 */
```

- `imu_init()` 开头 `dwt_init()`：`CoreDebug->DEMCR |= TRCENA`；`DWT->CYCCNT = 0`；`DWT->CTRL |= CYCCNTENA`；
  延时后读 `CYCCNT` 非零则 `g_dwt_ok = true`
- `icm_read_all()` 算出 dt，替换 `imu.c:204`（Fusion）与 `imu.c:166`（`yaw_gyro_accum_deg`）两处常数
- 兜底：`!g_dwt_ok` / 首帧 / dt 越界 → 退回 `IMU_DT_NOMINAL_S` 并 `g_dt_clamp_count++`

原理说明：dt 取连续两次**读取时刻之差**，求和望远镜式抵消，N 帧累计时间精确等于墙钟时间，
与 DRDY 相对 TIM6 tick 的相位抖动无关。单帧抖动是零均值误差，不累积。
**故不需要 FIFO、不需要在 EXTI 里读 SPI。**

顺带白拿一个 ISR 耗时探针（同一计数器）：`g_isr_max_us`，用于验证 ZUPT 滑窗统计在 `-O0` 下没吃爆 10 ms 预算。

### 改动 E：`gain` 0.01 → 0.3；SF 系数归位 —— 对应 F6

必须在改动 A 落地（gyro X/Y 不再被误清）之后才有意义。`accelerationRejection` 保持 10°，
`recoveryTriggerPeriod` 保持 200。预期只消掉倾角耦合的约 0.4%/5° 标度误差，**二阶量，不用它判断成败**。

`GYRO_Z_SF_POS / GYRO_Z_SF_NEG` 保持 1.0，注释改为：实测正负无剩余不对称（基线数据），
正负分离无依据；dt 已实测，其原始用途（补 ODR 标度误差）已消失。

## 【不做】

- **不换库**（VQF / ESKF / Madgwick）—— 6 轴 IMU 的 yaw 无绝对观测量，绕重力轴的自由度不可约束，
  所有滤波器在 yaw 上退化成同一件事：陀螺 z 积分。VQF（Laidig & Seel, *Information Fusion* 2023）是当前 SOTA，
  但其零偏 KF **只能从加速度计观测水平两个分量**，垂直（yaw）分量仍只在静止时可观测 ——
  相对"Fusion + 正经 ZUPT"在 yaw 上增量收益很小，代价是 ~1500 行 + 更多调参。ESKF 同样的可观测性天花板。
- **不做轮速差角速度融合** —— 本轮明确排除；`imu.c` 保持与 `encoder.h` 零耦合
- **不动 ROS 侧任何文件** —— `ekf_hw.yaml`、`stm32_serial_hw.cpp`、`hw_controllers.yaml` 一行不改
- **不改 0x02 串口帧格式** —— ROS 侧解析（`serial_utils.cpp:77`）零改动
- **不动 ODR（保持 100 Hz）、不启用 FIFO、不在 EXTI 里读 SPI**
- **不改 `-O0`** —— `Debug/*.mk` 是 CubeIDE 生成的，与 D 盘侧手改冲突；改用 `g_isr_max_us` 实测判断
- **不动 `main.c:121` 的 `HAL_Delay(2500)`**；**不写 0x0B 寄存器**
- ~~不改 `zupt.c`/`zupt.h`~~ —— **2026-08-26 撤销**，见 F8 与改动 F
- **不移植 VQF 全量**（`dlaidig/vqf`，MIT）—— rest detection 无法单独抽出，它是 `VQF::update()`
  内部状态机，依赖两组二阶巴特沃斯低通状态 + `restT` 计时器，且与 bias KF 的 R 矩阵切换耦合。
  要用就得整个 `vqf.cpp`（~1500 行）搬过来连 `FusionAhrs` 一起换掉，还要切 float 精度、
  重新整定 17 个参数。**而它在 yaw 上相对本方案的增量收益只有"打破自锁 + 零偏限幅"两条 ——
  这两条由改动 F 以 30 行拿到。**
- **不搬 `FusionOffset.c/h`**（Fusion 上游自带，本工程未搬入，已 `grep` 确认零命中）——
  判据只看 `|gyro|` 三轴瞬时阈值（默认 3 dps，比现有 0.57°/s 死区还松）、**无 accel 交叉验证**、
  **同样有自锁**（先减 offset 再比阈值，offset 又被拉向减完的残差）、无零偏限幅、静止时不强制输出 0。
  它是给手持/可穿戴做的简化件，**各项都弱于本工程已有的 `zupt.c`**。
- **不用 OpenShoe 的零速检测器**（Skog et al. 的 MV/MAG/ARE/SHOE）—— ZUPT 领域的学术标准参考，
  但判据基于足绑式行人 INS 的步态摆动相/支撑相能量差，轮式机器人没有对应结构，迁移不过来。
- **不用 ICM-42688-P 的 APEX WOM 做主判据** —— 硬件运动检测零 CPU 开销，但只有 accel 判据、
  阈值分辨率粗（mg/LSB 量级）、是为唤醒场景设计的中断源，不适合 100 Hz 连续状态判定。
  **可保留为后续的交叉校验**（硬件报"有运动"时强制退出 STATIC），本轮不做。

## 【异议】

1. **对"痛点是 Fusion 库不行"这个前提，我有异议。** Fusion 的集成与参数基本正确，问题全在输入端
   （零偏跟踪、死区、带宽、dt）。若不修这些而去换 VQF，dt 仍是常数、死区仍在，**yaw 一分不改善**。
   故本方案不含换库。
2. **改动 A 存在明确的倒退风险，必须点名。** 拆掉死区等于拆掉一根拐杖：
   实测零偏 0.0118 °/s 远低于死区阈值 0.57°/s，**现在死区把它在直线行驶时也一并挡住了**；
   换成 ZUPT 后，MOVING 段这个零偏会持续积分（连续行驶 10 min ≈ 7°）。
   所以 ZUPT 的在线零偏跟踪不是锦上添花，是改动 A 能否不倒退的**前提**。
   缓解：业务闭环（召唤→上门→等待→归位）本就周期性停车，STATIC 窗口充足；
   验收 A3 明确写了"不得比改前基线更差"。**仍按此方案做**，但若 A3 倒退，
   正确的回退不是恢复死区，而是补做轮速差融合（见异议 3）。
3. **对"只做固件、不碰轮速"，我有异议，但仍按用户所说的做。** 6 轴 IMU 的 yaw 在行进中不可观测是数学事实；
   本方案上限是"把积分做干净"。长时间连续行驶的 yaw 仍会漂，这是天花板，不是实现缺陷。
   唯一的质变项是轮速差角速度 `(v_R−v_L)/tread` —— 它是唯一能在**行进中**观测 gz 零偏的量。
   顺带记录：`ekf_hw.yaml` 的 `odom0_config` 第 12 位（vyaw）注释写着
   "encoder yaw rate anchors IMU drift"，但值是 `false` —— 注释描述的机制并没有开启。本轮不动它。
4. **规划中出过两次错，已改正，记此备查：**

   - 预测 F1（dt）是主因、量级约 1%。台架实测 **0.118%**，**预测错误**，改动 D 已从主刀降为顺手做。
     教训：把"代码里是常数"（事实）直接当成"误差很大"（假设），中间少了一次实测。
   - 声称手册要求 STATIC 寄存器在传感器关闭时写入 —— 手册无此明文，**是编造的**；
     同时把 AAF 默认带宽说成 258 Hz，实为陀螺 585 Hz / 加速 1220 Hz。均已依手册改正。
5. **台架基线的适用范围要写在脸上，避免后人误用。** 那组数是**电机断电手推**测的，
   0.0118 °/s 是零偏地板而非行驶工况值。任何人拿这组数论证"现状已经够好"都是误读 ——
   它恰恰没覆盖实际抱怨的工况（通电行驶）。这也是为什么本方案在实测标度误差仅 0.118% 的情况下
   仍然全量执行，而不是收缩到"只修 dt"。
6. **（2026-08-26 复审）用户"还是需要点死区"的判断成立，我原卡的表述有误导。**
   原卡把改动 A 写成"删掉死区"，隐含"ZUPT 能全面替代死区"。**这是错的** ——
   ZUPT 只在 STATIC 态强制归零，MOVING 段完全不做抑制，纯裸积分。旧死区之所以"看起来压得住"，
   恰恰因为它在直线行驶时**也是 ON**（实测零偏 0.0118 °/s 远低于阈值 0.57 °/s），把漂移直接抹成 0 ——
   用"慢转不可观测"换来的。所以正确表述是：**换掉旧死区，不是删掉死区**。已增补改动 A-2。

   顺带记：**这是本议题上我第三次把"代码里写着什么"当成"它实际起什么作用"**
   （前两次见异议 4）。旧死区的三个 bug（只看单轴、误清 X/Y、作用于未减零偏的原始值）都是真的，
   但"它是个 bug"不等于"它没在干活"。删除一个有 bug 的机制之前，先问它现在实际压住了什么。
7. **（2026-08-26）选型结论：不换库，修自己的 `zupt.c`。** 候选与判据已一次列全给用户勾选
   （VQF 全量 / FusionOffset / OpenShoe / APEX WOM / 改自己的），用户选了最后一条。
   依据是 F8 的两条缺陷（自锁、无限幅）在 VQF 里的解法只是"用常量 `biasClip` 绝对上界替代
   与 bias 的比较"+"零偏钳位"，共 30 行，不需要为此搬 1500 行和 17 个新参数。
   **但 `bias_clip` 这个名字和思路是从 VQF 抄的，出处记在此，不是我原创。**

### 第 0b 步细则（2026-08-26 新增）

烧现固件即可，不需要先改代码。CubeIDE Live Expressions 挂 `g_imu.gyro[2]`、`g_imu.accel[0..2]`。

| 工况                | 测什么                                             |
| ------------------- | -------------------------------------------------- |
| ① 断电静置         | 噪声底真值                                         |

| ③ 直线行驶 30% PWM | 行驶工况方差（这是 MOVING 判据实际要越过的门槛）   |

- `gyro_var_thresh` 取 ①② 中较大者 × 9（3σ），`accel_var_thresh` 同理

## 【执行结果】2026-08-27 落地并验收

代码落在 `imu.c` / `imu.h` / `zupt.c` / `zupt.h` 四个文件，ROS 侧一行未动。
下面记录**与本卡不一致的地方**和实测数字，卡的正文保持原样不改 —— 那是当时的判断快照。

### 三处实质偏离

**偏离 1：改动 F 第 2 点的方案被实测推翻。**

卡里写的是「`is_window_static()` 追加绝对上界 `|gyro_mean[i]| > bias_clip`」。
实现时先按此思路新增了 `gyro_mean_abs_thresh` 字段（取 2.0e-3 rad/s），
烧录后实测 **ZUPT 一次都进不了 STATIC**（静止 1392 帧，`angular_velocity` 三轴全零帧 = 0）。

根因：`gyro_mean` 是**未减零偏**的原始均值，而器件原始零偏实测
x = 0.266 / y = −0.197 / z = **0.306** °/s，三轴全部超过该阈值。
更根本的是这条判据**结构上无解** —— 它要同时大于原始零偏（0.3 °/s）
又小于要否决的慢转（A8 的 0.3 °/s），区间为空；且慢转与零偏反向时偏离量反而更小。

最终方案：**删除 `gyro_mean_abs_thresh`**，判据回到已有的 `gyro_mean_thresh`
（判的是「窗口均值 − 当前零偏」的偏离量），阈值 0.01 → **2.0e-3**（0.573 → 0.115 °/s）。
下界由标定后的残余漂移定（实测约 0.012 °/s，约 10× 余量），上界由必须否决慢转定。

同一条判据在 `should_exit_static()` 里补了一份。**本卡漏掉了一件事**：
状态机进入 `ZUPT_STATIC` 后就不再调 `is_window_static()`，只走 `should_exit_static()`，
所以只加在前者里挡不住「先停住、再开始匀速慢转」这个序列 —— 而那正是实际工况。

**偏离 2：H6 不成立，accel 判据废弃，但不需要引入轮速。**

第 0b 步实测（滑窗方差，与 `zupt.c` 的 `accel_var_sum` 同口径）：


| 工况                       | 中位数  | max     |
| -------------------------- | ------- | ------- |
| ① 断电静止（ROS 侧算）    | 0.00018 | 0.0592  |
| ③ 直线行驶（ROS 侧算）    | 0.00053 | 0.00245 |
| 电机通电静止（固件内直读） | 0.00055 | —      |
| 直线行驶（固件内直读）     | 0.00053 | —      |

行驶方差不高于静止，**H6 不成立**，`accel_var_thresh` 在本机上没有鉴别力。
0.5 → **0.1**，只保留挡撞击 / 被搬动的作用。

但卡里预备的回退方案（引入 `encoder.h` 的轮速）**没有启用** —— 实测证明 gyro 判据够用：
直线行驶 15 s，三轴全零帧 **0 / 1387**，ZUPT 全程未进 STATIC。
`imu.c` 与 `encoder.h` 的零耦合约束保持。

**偏离 3：`settle_samples` 25 → 500（0.25 s → 5 s）。**

用户提出，依据是业务闭环的等待段本就是长静止，加长确认期能排除运动中的短暂平静期
（转向前的停顿、避障刹停）。零偏温漂率实测很慢，代价可忽略。
⚠️ 它对匀速慢转无效 —— 那种情形方差本来就低，拦它的是 `gyro_mean_thresh`。

### 另外两处调整

- **`CYC_TO_SEC` 没写死 72 MHz**，改为运行时取 `SystemCoreClock`。卡里那个值是
  `main.c` 时钟配置的数值副本，会过时。
- **`g_isr_max_us` 的口径要注意**：它测的是 `icm_read_all()` 的耗时，
  **不含** TIM6 ISR 里的 PID 与串口打包。A7 的判定按此口径，达标不等于整个 ISR 预算达标。
