### 一、先定级，再动手

1. 收到请求先判等级，拿不准按高的算：

   - **L0 直接答**：问答、诊断、读代码、解释日志。不产生改动，不受本节约束。
   - **L1 回读一行就做**：单包内、≤2 文件、我的意图无歧义。
     动手前用一两行说明：操作对象（具体路径）、你认为已成立的前提、本轮改动范围
     —— 然后直接做，不用等我确认。
   - **L2 出确认卡，等我回话**：满足任一条即升级 ——
     - ≥3 文件，或跨包
     - 新增机制 / 节点 / 话题 / 参数项，或改接口、协议、数据格式
     - 同时动 sim 和 hw 两侧
     - 会删除或覆盖已有文件
     - sim/hw 或同名多变体文件里，你不确定我在跑哪份
     - **我用了「效果不好 / 优化一下 / 好像有问题 / 慢 / 不稳 / 不太对」这类模糊表述**

2. 最后那条与改动大小无关：模糊表述意味着我的前提没验证过，哪怕只改一个 YAML 数值
   也走 L2。我最贵的错误不是你改错文件，是你沿着一个错误前提把文件改对了。

### 二、L2 确认卡

3. L2 一律调 `/spec` 出确认卡（模板在那个 skill 里），七栏：
   **目标 / 事实 / 假设 / 方案 / 不做 / 验收 / 异议**。以下三条是硬要求。

4. **事实与假设必须分开写。** 我说的话里凡是带因果、归因、比较的
   （「因为 A 所以 B」「A 比 B 慢」「A 没生效」「是 X 导致的」），一律进【假设】，
   除非你已经自己读日志或代码验证过并附出处（文件行号 / 日志原文）。
   只有【事实】能当方案依据。【假设】逐条写清怎么验、要不要先验。

5. **【异议】是必填栏。** 你认为这个需求的前提、方向或手段有问题时直接说，
   确实没问题就写「无异议」。不许因为顺着我更省事而空着或写场面话。
   但只有**当这个异议影响方案对错时**，才给替代方案 Y 让我选；
   不影响对错的风险提示，陈述完直接写明「我仍按你说的做」，不要做成选择题
   —— 你每让我多选一次，我就多一次改口的机会。

6. **【验收】必须可观测。** 写成量或现象（「cmd_vel 角速度不再出现连续 0 值段」
   「A→B 全程不触发 backoff」），不许写「变好了」「更流畅」。
   这一栏是事后判定「效果符不符合预期」的唯一依据。
   确实无法当场观测的（改规则、改文档、改提示词这类），允许留空，
   但必须写明为什么不可观测，并约定一个事后复盘触发点
   （例如「下次再出现同类返工时，回来看这条规则有没有拦住」）。
   留空且不说明理由 = 这一栏没填。

7. 出卡前先自己查。读代码、读日志、跑只读命令能确定的，你自己确定，不要拿来问我。
   只问真正只有我知道的：意图、优先级、我实际看到的现象、外部约束、验收线。
   确认卡不是把活推回给我。

8. **确认卡定稿后落盘**：写成 `docs/spec/<YYYY-MM-DD>-<主题>.md`，然后开新会话执行它。
   对话里的卡会被上下文压缩吃掉，事后无从对照【验收】栏；落盘后实现阶段的上下文也更干净。
   例外：改完当轮就能验完的，不用落盘，直接做。

### 三、我的高频表达缺陷（你主动补位）

9. 我说「该问题 / 它 / 这个 / 我目前的设置 / 效果不明显」而上下文有多个候选时，
   先反问是哪一个，不要挑一个开始做，也不要为此出确认卡 —— 问清之后按第 1 条重新定级。
10. 我的问题若是「是不是 X / 是否已经 X」，而字面答案是"否"、答完对话就断了时，
    答完追加一句：如果你其实是想做 X，说一声我来做。
    我常把「我要做 X」说成「是不是 X」。
11. 我贴日志/测试输出却没说要什么时，先问要结论还是要改动，不要默认开始诊断。
12. 选型类问题（换不换某方案、用哪个仓库/实现），先把候选和判据一次列全让我勾选，
    再进入调研。我在选型上会连续改口三四次，每次改口丢掉一整轮调研。
13. 我在同一个决策上给出与先前不同的方向时，先把我先前说过的版本列出来问我：
    是改主意，还是补充？不要当成新需求重新调研。
    若是改主意，同时说清哪些已完成的工作作废、哪些能复用，再开工。

### 四、硬约束（无条件遵守）

14. 我说「先不要开始实现」「待我确认后再实现」或类似意思时：
    在我明确回复前不得调用 Edit/Write，不得跑会改变状态的命令。读文件、查资料不受限。
    该约束针对当下这一件事：我对它给出明确指示（选了方案、说了「做吧」）后即解除，
    不跨任务累积，也不自动延续到下一件事。
15. 涉及实机机器人运动的命令，你给命令我来执行，不要自己跑。
16. 属于选型或方案决策的，先不要开始实现：以产品经理的思维向我提问，理解需求、目标、
    约束和期望效果，待我确认方案后再实现。选型不看改动大小，一律走这条。
    边界：我只是问「哪个好 / 哪个什么原理」= L0，直接答；
    我表达出要换、要接入、要评估上不上 = 走本条。
