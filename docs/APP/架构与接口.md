# 架构与接口

> 行号对应上游 commit `88ad742`。升级上游后若对不上，以代码为准并回来更新本文。

## 它是什么

[ROS_Flutter_Gui_App](https://github.com/chengyangkj/ROS_Flutter_Gui_App)，C/S 架构：

| 组件 | 是什么 | 在哪 |
| --- | --- | --- |
| `ros_gui_backend` | 机器人侧 C++ 后端（drogon HTTP + rclcpp 节点），单个可执行文件 | 部署在 `~/ros_flutter_gui/` |
| 前端 | Flutter Web，构建产物是**纯静态文件**（跨平台，与 CPU 架构无关） | `~/ros_flutter_gui/dist/` |
| 源码 | 上游 clone，**push 不上去**；本地改动见 [patches/](patches/) | `~/ROS_Flutter_Gui_App/` |

**它不参与 colcon 构建**，和 `dev_ws` 是两个独立的东西 —— 靠 ROS 话题/服务和 `~/.maps/` 目录耦合。
（也正因如此不要把它塞进 `dev_ws/src/`：`backend/CMakeLists.txt` 会被 colcon 误认成包。）

后端 ROS 节点名：**`ros_gui_app_backend`**（`node/ros2/node.cpp:125`）。

## 配置

两份，**`gui_app_settings.json` 覆盖 `cfg/config.yaml`**（后端以 `--config-json` 加载它）：

```bash
~/ros_flutter_gui/gui_app_settings.json   # 实际生效的
~/ros_flutter_gui/cfg/config.yaml         # 默认值
```

字段含义与填错的症状见 [复现与部署.md](复现与部署.md#配置字段)。

## HTTP 接口

后端监听 `:8080`（`cfg/config.yaml` 的 `web_server.port`）。注册点：`core/web_server/web_server.cpp`。

| 路由 | 方法 | 用途 |
| --- | --- | --- |
| `/getAllMapList` | GET | 列出 `~/.maps/` 下所有地图名 |
| `/currentMap` | GET | 当前地图 → `{"current_map":"my_map"}` |
| `/setCurrentMap?name=<n>` | GET | 切换当前地图（写 `~/.maps/current_map`） |
| `/deleteMap?map_name=<n>` | GET | 删除一张地图 |
| `/getTopologyMap[?map_name=<n>]` | GET | 取拓扑（导航点） |
| **`/saveMapEdit`** | GET | **保存画笔编辑，也是「新建/另存」地图的唯一入口**，见下 |
| `/tiles/{map_name}/{z}/{x}/{y}` | GET | 瓦片 |
| `/tiles/{map_name}/meta`、`/config` | GET/POST | 瓦片元信息 / 层级配置 |
| `/robot/nav_goal`、`/robot/initial_pose`、`/robot/cancel_nav` | POST | 导航控制 |
| `/api/settings`、`/api/tf`、`/subImage` | — | 设置、TF、图像流 |

### `/saveMapEdit`（最重要）

GET，5 个 query 参数：`session_id`、`map_name`、`source_map_name`、`topology_json`、`obstacle_edits_json`。

实现在 `core/map/map_manager.cpp:190-265`（`ApplyMapEditFromQuery`），逻辑是：

1. 试着加载 `~/.maps/<map_name>/<map_name>.yaml`
2. **加载失败就回退到 `source_map_name`** ← **这就是「新建/另存地图」的路径**
3. 建目录 → 把 `obstacle_edits_json`（画笔：`{"格子下标": 100}`）套到栅格上
4. 写 `<map_name>.pgm` / `.yaml` / `.topology`，**并生成 tiles**

所以 app 上的「另存为」按钮 = 用一个新名字调它。这一点导致了[设计取舍 2](#2-另存为只产出半张地图)。

## `~/.maps/` 契约

```
~/.maps/
├── current_map          # 纯文本，一行地图名。app 选图时写，ROS launch 启动时读
├── map/                 # 【保留名】后端从 MapSubTopic 持续镜像的实时快照
└── <name>/              # 一张正式地图
    ├── <name>.posegraph / .data   # slam_toolbox 定位（由 save_map.sh 产出）
    ├── <name>.yaml / .pgm         # 栅格图（原图+画笔）= 同时就是 keepout 掩码
    ├── <name>.topology            # 导航点
    └── tiles/                     # 前端瓦片
```

**目录名和文件名必须一致**：`~/.maps/<name>/<name>.yaml`。

根目录来自 `$HOME/.maps`（`core/map/map_manager.cpp:31`）。

ROS 侧怎么消费这套契约（多地图切换、keepout 掩码），见
[my_bot_nav/docs/多地图与禁行区.md](../../src/my_bot_nav/docs/多地图与禁行区.md)。

## 设计取舍

这三条是**代码里看不出来、但违反了就出错**的地方。

### 1. 地图名不能叫 `map`

`core/map/map_manager.cpp:362` 把 `default_map_name` **硬编码**为 `"map"`。后端会把
`MapSubTopic` 收到的地图**持续镜像**进 `~/.maps/map/`（`UpdateDefaultMap`，line 334-380）。

- **违反的症状**：正式地图取名 `map` → 你画的禁行区被 slam 的实时地图周期性覆盖、悄悄消失
- **为什么安全**：镜像**只写 `map` 这一个目录**，其他名字的地图它碰都不碰
- **顺便**：这份被持续刷新的 `~/.maps/map/` 正好是"当前 slam 地图 + 现成 tiles"的快照，
  `save_map.sh` 存新图时就是拿它当复制源

> 历史包袱：上游默认 `MapSubTopic: /map`，早期为了防覆盖曾把它改订 `/map_gui` 并加了个转发节点。
> 现在靠"地图不重名"这条约束就够了，`MapSubTopic` 已改回 `/map`，转发节点和 diff 节点都已删除。

### 2. 「另存为」只产出半张地图

app 的「另存为」走 `/saveMapEdit`，它**只复制源图的栅格 + 套画笔**，
根本不知道 slam 的存在 → **不产出 posegraph**。

- **违反的症状**：另存为一张图、选中它、起 slam localization → 报错找不到 `<name>.posegraph`
- **为什么能救**：另存为**保持几何完全不变**（同 width/height/resolution/origin），
  所以**源图的 posegraph 对派生图完全有效**
- **怎么救**：`slam.launch.py` 会自动认亲 —— 发现缺 posegraph 时，按
  **几何完全一致 + 像素相似度 ≥90%** 找出源图并复制过来（补一次，之后这张图就自足了）

| 建图方式 | posegraph | pgm + tiles |
| --- | --- | --- |
| `save_map.sh <名字>`（mapping 模式下） | ✅ | ✅ |
| app 的「另存为」 | ❌（自动认亲补齐） | ✅ |

> `slam_toolbox` 的 `serialize_map` 服务**在 localization 模式下会被拒绝**，
> 但**照样返回 `result=0`**。所以 `save_map.sh` 靠文件新鲜度判断成败，不能只看返回码。

### 3. cache-buster 只能放 URL、不能放 key

`app/lib/display/tile_map.dart` 的 `TileLayer`。后端保存画笔后**原地重写**瓦片（URL 不变），
于是有两个必须同时绕开的坑：

| 做法 | 后果 |
| --- | --- |
| `key: ValueKey('..._$_tileCacheBuster')` | key 一变 → **整个 TileLayer 重建**、清空 fallback 缓存 → 小图（前端请求高 zoom，而瓦片只生成到 z=5，平时靠低层级放大兜底）**整图空白闪烁** |
| `urlTemplate` 不带 `?_ts=` | URL 不变 → 浏览器一直吃缓存 → **画笔保存后不显示，必须硬刷新** |

**正解**：key 保持 `ValueKey('tile_layer_$_currentMapName')` 稳定，`urlTemplate` 带 `?_ts=$_tileCacheBuster`，
且 `_tileCacheBuster` **只在"地图保存成功"这个离散事件上变一次**
（`map_edit_page.dart` 两个保存点各 bump 一次 `globalSetting.MapTileStyleEpoch`）。

上游原版是用一个 5s 定时器不断改 `_tileCacheBuster` 且同时进了 key 和 URL —— 那正是闪烁的根源。
补丁把定时器删了。见 [patches/](patches/)。
