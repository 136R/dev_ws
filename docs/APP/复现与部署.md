# 复现与部署

写成「命令 + 断言」的序列。每步跑完能自判成败，不需要人来看。

---

## A. 开发机（WSL / x86，跑仿真）

### 1. 取源码（我们的 fork，改动已在里面）

```bash
git clone https://github.com/136R/ROS_Flutter_Gui_App.git ~/ROS_Flutter_Gui_App
cd ~/ROS_Flutter_Gui_App
git remote rename origin fork
git remote add origin https://github.com/chengyangkj/ROS_Flutter_Gui_App.git   # 上游，用来拉更新
```

**断言**：`git log --oneline -2` 里能看到 `feat(task): 底部任务卡…` 和 `fix(tiles): 瓦片 cache-buster…`

> **不用打补丁了。** 早期没 fork 时，前端改动靠 `docs/APP/patches/` 里的 diff 维护；
> 现在它们就是 fork 里的普通 commit。patches 目录已删。

### 2. 取后端可执行文件

后端是预编译的（本仓库不构建它）。从上游 Release 下 **x86_64** 那份 zip，解到 `~/ros_flutter_gui/`。

**断言**：
```bash
ls ~/ros_flutter_gui/{ros_gui_backend,start.sh,cfg/config.yaml} && \
  ~/ros_flutter_gui/ros_gui_backend --help >/dev/null && echo OK
```

### 3. 写配置

`~/ros_flutter_gui/gui_app_settings.json`，字段见[下方](#配置字段)。

**断言**：
```bash
python3 -c "import json;d=json.load(open('$HOME/ros_flutter_gui/gui_app_settings.json'));\
assert d['MapSubTopic']=='/map' and d['MapPubTopic']=='/map_manager/map';\
assert not any(isinstance(v,str) and v!=v.strip() for v in d.values()), '有字段带首尾空格';print('OK')"
```

### 4. 构建前端

```bash
export PATH="$HOME/flutter/bin:$PATH"
export PUB_HOSTED_URL=https://pub.flutter-io.cn FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
cd ~/ROS_Flutter_Gui_App/app && flutter pub get && flutter build web --release
```

**断言**：末尾出现 `✓ Built build/web`；`flutter --version` 应为 **3.29.3 stable**。

### 5. 部署 dist

```bash
cd ~/ros_flutter_gui
rm -rf dist.bak && cp -a dist dist.bak            # 备份，回滚用
rm -rf dist && cp -a ~/ROS_Flutter_Gui_App/app/build/web dist
```

**断言**：`grep -c "_ts=" ~/ros_flutter_gui/dist/main.dart.js` → 非 0（cache-buster 进产物了）
**回滚**：`rm -rf dist && mv dist.bak dist`

### 6. 起后端

```bash
cd ~/ros_flutter_gui && sh ./start.sh
```

**断言**：`curl -fsS localhost:8080/getAllMapList` 返回 JSON 数组。
**常见失败**：`Bind address failed at 0.0.0.0:8080` = 已经有一个后端在跑，先 `pkill -f ros_gui_backend`。

> 浏览器开 `http://127.0.0.1:8080`，**换过 dist 后必须 Ctrl+Shift+R 硬刷新**
> （Service Worker 会缓存旧版；必要时 F12 → Application → Service Workers → Unregister）。

## 改前端

日常最常做的事。**源码在 `~/ROS_Flutter_Gui_App/`，产物在 `~/ros_flutter_gui/`。**

```bash
# 1. 改源码
vim ~/ROS_Flutter_Gui_App/app/lib/...

# 2. 重编 + 重新部署（= 上面的第 4、5 步）
export PATH="$HOME/flutter/bin:$PATH"
cd ~/ROS_Flutter_Gui_App/app && flutter build web --release
cd ~/ros_flutter_gui && rm -rf dist.bak && cp -a dist dist.bak \
  && rm -rf dist && cp -a ~/ROS_Flutter_Gui_App/app/build/web dist

# 3. 浏览器 Ctrl+Shift+R 硬刷新

# 4. 提交并推到 fork
cd ~/ROS_Flutter_Gui_App && git add -A && git commit && git push fork main
```

> **⚠️ 别改 `~/ros_flutter_gui/dist/` 里的东西** —— 那是编译产物，下次部署 `rm -rf dist` 就没了。
> （`gui_app_settings.json` 是例外：它是运行时配置，不在源码仓库里，也不会被部署覆盖。）

### 拉上游更新

```bash
cd ~/ROS_Flutter_Gui_App
git fetch origin && git merge origin/main      # origin = 上游 chengyangkj
# 有冲突基本只会在 tile_map.dart 的 TileLayer 那一段，见架构与接口.md「设计取舍 3」
git push fork main
```

## B. 实机（香橙派 5 Pro / arm64）

**机器人侧不需要装 Flutter。** `dist/` 是纯静态文件、跨平台，直接复用开发机构建好的那份。

1. 机器人侧取 **arm64 后端**：上游 Release 的 `backend-<tag>-arm64.zip`
   （它自带一份**上游原版**的 `dist`，没有我们的改动）
2. 用开发机构建好的 `dist/` 覆盖它自带的：
   ```bash
   rsync -a --delete <开发机>:~/ros_flutter_gui/dist/ ~/ros_flutter_gui/dist/
   ```
   **断言**：`grep -c "_ts=" ~/ros_flutter_gui/dist/main.dart.js` → 非 0（cache-buster 在）
3. 写 `gui_app_settings.json`（话题/帧名按实机栈填，见下）
4. ROS 侧照常起 slam + nav（`nav.launch.py` 已内含 keepout 流水线）
5. 要用任务卡的话，还得起任务层：`ros2 launch my_bot_task task.launch.py`
   （它自开 `:8090`，前端会去轮询。没起也不影响 app，只是任务卡不显示。
   见 [my_bot_task/docs/](../../src/my_bot_task/docs/)）

## 配置字段

`~/ros_flutter_gui/gui_app_settings.json`。**任何字段都不能带首尾空格 —— app 不会 trim。**

| 字段 | 值（仿真） | 为什么 / 填错的症状 |
| --- | --- | --- |
| `MapSubTopic` | `/map` | 后端把它持续镜像进 `~/.maps/map/`，这份镜像是 `save_map.sh` 的复制源。**前提是正式地图不叫 `map`**（否则画笔被覆盖，见架构文档「设计取舍 1」） |
| `MapPubTopic` | `/map_manager/map` | 别用默认的 `/map` —— 会和 slam 抢发布、污染 costmap 静态层 |
| `BaseLinkFrameName` | `base_footprint` | 本车 EKF 输出 `odom→base_footprint`。**带尾随空格会导致 TF 查找静默失败** |
| `SpeedCtrlTopic` | `/cmd_vel_keyboard` | 接进 TwistMux 的高优先级输入 |
| `LaserTopic` | `/scan` 或 `/scan_filtered` | 按实际栈 |
| `OdomTopic` | `/odometry/filtered` | EKF 输出 |
| `RelocTopic` | `/initialpose` | 重定位按钮 |
| `GlobalPathTopic` / `LocalPathTopic` | `/plan` / `/local_plan` | |
| `GlobalCostmapTopic` / `LocalCostmapTopic` | `/global_costmap/costmap` / `/local_costmap/costmap` | |

实机改的主要就是话题名和帧名，其余同仿真。

## 排错

| 症状 | 原因 |
| --- | --- |
| 画笔保存后网页不显示 | dist 没换 / 没硬刷新 / 部署的是上游原版产物（`grep -c "_ts=" dist/main.dart.js` 应非 0） |
| 画笔保存后机器人不绕行 | `keepout_mask_reloader` 没起来，见 [多地图与禁行区.md](../../src/my_bot_nav/docs/多地图与禁行区.md) |
| 画的禁行区过一会儿自己没了 | 地图名叫了 `map`，被实时镜像覆盖 |
| slam 报找不到 `<name>.posegraph` | 这张图是 app「另存为」出来的且认亲失败 → 说明是全新场地，用 `mode:=mapping` + `save_map.sh` |
| `Bind address failed at 0.0.0.0:8080` | 已有后端在跑 |
| **WSL 下访问 8080 得到 `502 Bad Gateway`** | **后端根本没跑**（不是它内部出错）。WSL2 的 localhost 与 Windows 打通，WSL 里没人监听 8080 时请求会漏到 Windows 那边、被别的东西接住并回 502。后端自己的错误码里**没有 502**（只有 400/404/500/503）—— 看到 502 就去起后端 |
| `save_map.sh` 第 2 步失败 | 后端没跑。脚本已加前置检查，正常会在序列化之前就拦住并提示 |
| 遥控时地图整图闪烁 | 部署的是上游原版产物（那个 5s cacheBuster 定时器还在），重编我们 fork 的源码 |
| app 上没有底部任务卡 | ① 任务层 `my_bot_task` 没起；② `:8090` 不通（`curl localhost:8090/task/status`）；③ 待命时本来就整张隐藏，先召唤一个房间 |
