# 代码与文档规范

**完整规范在 `docs/代码与文档规范.md` —— 动手前读它。**

下面三条是最容易违反的，先记住：

1. **默认不写注释。** 只在四种 WHY 非显然的情况写：隐藏约束 / 跨文件耦合的不变量 /
   针对具体 bug 的 workaround / 违反后会出症状的反直觉行为。
   复述代码在干什么的注释直接不要。

2. **注释和文档引用别处的值时，只写指针，不写数值。**
   `见 robot_config.h 的 CONTROL_FREQ_HZ`，不是 `100Hz`。
   例外：值就定义在注释下一行时，可以写推导过程。

3. **指针用 `文件` + `键名`，禁止行号。**
   `` `ekf_hw.yaml` 的 `imu0` ``，不是 `ekf_hw.yaml:28`。
   行号会漂，漂了之后 AI 直接信错行 —— 比没有指针更糟。

改到存量英文注释时不用翻译，本仓库只约束新写和改动碰到的部分。
