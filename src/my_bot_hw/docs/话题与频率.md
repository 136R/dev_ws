> `ros2 launch my_bot_hw robot_bringup.launch.py` 起来之后，数据怎么流、各环节跑多快。
> 数值全部核对自 `config/*.yaml` 与 `firmware/my_robot_stm32/Core/Inc/app/robot_config.h`。

## 速度指令流

```
键盘/app 遥控          Nav2
      │                  │
/cmd_vel_keyboard   /cmd_vel_nav
   (优先级 90)        (优先级 70)
      └────────┬─────────┘
            twist_mux          ← 优先级仲裁；0.5s 无指令自动停
               │
   /diff_cont/cmd_vel_unstamped
               │
           diff_cont           ← diff_drive_controller
               │
   Stm32SerialHardware::write()
               │
   /dev/ttyS7 @115200 → STM32F303
   0x01 帧 [vx, 0, vyaw]（int16 ×1000，大端）
```

**速度限制**（`config/hw_controllers.yaml`）：线速度 `-0.3 ~ +0.4 m/s`（加速度 ≤1.5 m/s²）、
角速度 `±1.2 rad/s`（加速度 ≤2.0 rad/s²）。

> 底盘物理上限约 **0.885 m/s**（`robot_config.h`），ROS 侧刻意限得更保守。

## 里程计流

```
STM32F303  ← 控制环 100 Hz（CONTROL_FREQ_HZ）
   │ 0x0A 帧 [vx_mm/s, vyaw_mrad/s, yaw_cdeg]（int16 大端）
   │
Stm32SerialHardware::read()          ← 18ms 超时
   │ 解算 v_left/right = (vx ± vyaw·L/2) / R
   │
diff_cont（diff_drive_controller）    ← enable_odom_tf: FALSE，不发 TF
   │
/diff_cont/odom  ──odom_relay──→  /odom
                                     │
imu_broad → /imu_broad/imu ──────────┤
                                     ▼
                            ekf_filter_node @100Hz
                                     │
                    /odometry/filtered + TF odom→base_footprint
                                     │
                            slam_toolbox / Nav2
```

> ⚠️ **TF 只有 EKF 发。** `diff_cont` 的 `enable_odom_tf: false`
> （`hw_controllers.yaml:39`），EKF 的 `publish_tf: true`（`ekf_hw.yaml:11`）。
> 两处都发会打架。
>
> ⚠️ **EKF 吃的是 `/imu_broad/imu`，不是 `/imu/data`。**
> `ekf_hw.yaml` 里那行 `# imu0: /imu/data`（走 `imu_complementary_filter`）**是注释掉的**。
>
> `odom_relay` 是必需的：`diff_drive_controller` 固定发 `/diff_cont/odom`，而 EKF 订阅 `/odom`。

**关键几何**（`hw_controllers.yaml` —— 里程计几何的真相源，固件那两个宏是死代码）：
`wheel_separation: 0.192` m、`wheel_radius: 0.035` m（2026-08 底盘重做后实测；
三个 multiplier 已复位 1.0，待重新标定）。

## TF 树

```
map                       ← slam_toolbox（50 Hz，transform_publish_period: 0.02）
 └── odom                 ← ekf_filter_node（100 Hz）
      └── base_footprint
           └── base_link                    ← robot_state_publisher（静态）
                └── chassis
                     ├── laser_frame        （静态，雷达外参）
                     ├── caster_front/back_wheel
                     ├── left_wheel         （随 /joint_states）
                     └── right_wheel        （随 /joint_states）
```

> `view_frames` 里静态 TF 显示 `rate: 10000` 属正常（latched，与频率无关）。

## 频率一览

**全链路 100 Hz** —— STM32 控制环、controller_manager、EKF 三者同频，这是刻意对齐的。

| 环节 | 频率 | 参数 | 出处 |
| --- | --- | --- | --- |
| STM32 控制环 | **100 Hz** | `CONTROL_FREQ_HZ 100` | `firmware/.../robot_config.h` |
| `controller_manager` | **100 Hz** | `update_rate: 100` | `hw_controllers.yaml:3` |
| `diff_cont` 发里程计 | **100 Hz** | `publish_rate: 100.0` | `hw_controllers.yaml:16` |
| `ekf_filter_node` | **100 Hz** | `frequency: 100.0` | `ekf_hw.yaml:3` |
| `sllidar_node` | 10 Hz | — | 思岚 C1 标准扫描模式 |
| `slam_toolbox` 发 TF | 50 Hz | `transform_publish_period: 0.02` | `mapper_params_hw.yaml` |
| Nav2 `controller_server` | 20 Hz | `controller_frequency: 20.0` | `my_bot_nav/config/hw/nav2_params_hw_*.yaml` |
| Nav2 `planner_server` | 1 Hz | `expected_planner_frequency: 1.0` | 同上 |
| Nav2 local costmap | 20 Hz 更新 / 1 Hz 发布 | `update_frequency` / `publish_frequency` | 同上 |
| Nav2 global costmap | 1 Hz / 1 Hz | 同上 | 同上 |
| Nav2 `behavior_server` | 10 Hz | `cycle_frequency: 10.0` | 同上 |
| 行为树 | 100 Hz | `bt_loop_duration: 10`（ms） | 同上 |

### 超时阈值

| 参数 | 值 | 含义 | 出处 |
| --- | --- | --- | --- |
| `sensor_timeout` | 0.08 s | 传感器静默超此值，EKF 丢弃该源 | `ekf_hw.yaml` |
| `cmd_vel_timeout` | 0.5 s | 无指令则 diff_cont 停车 | `hw_controllers.yaml:48` |
| 串口 read 超时 | 18 ms | 超时则本周期跳过，不阻塞 | `src/stm32_serial_hw.cpp` |
| slam `transform_timeout` | 0.5 s | TF 查询超时 | `mapper_params_hw.yaml` |

### 关键约束

| 约束 | 核对 |
| --- | --- |
| `sensor_timeout ≥ 2 × (1/传感器频率)` | `0.08 s ≥ 2 × 10 ms = 0.02 s` ✅（4 倍余量） |
| EKF 频率 ≥ 最快传感器频率 | `100 Hz = 100 Hz`（`/odom` 与 `/imu_broad/imu` 均 100 Hz）✅ |
| STM32 与 controller_manager 同频 | `100 Hz = 100 Hz` ✅ |

## 节点启动顺序

用 `TimerAction` 分级延迟 —— spawner 必须等 `controller_manager` 的服务就绪。

| 时刻 | 节点 |
| --- | --- |
| t=0 | `robot_state_publisher`、`ros2_control_node`（打开 `/dev/ttyS7`）、`sllidar_node`、`laser_filter`、`twist_mux`、`odom_relay` |
| t=2.0s | spawner `joint_broad` |
| t=2.5s | spawner `imu_broad` |
| t=3.0s | spawner `diff_cont` |
| **t=4.0s** | `ekf_filter_node`（等 `imu_broad` 就绪） |

> 起完 launch 别立刻发指令 —— **至少等 4 秒**。
