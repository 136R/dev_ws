# 话题与频率（实机）

> `ros2 launch my_bot_hw robot_bringup.launch.py` 起来之后，数据怎么流、各环节的速率由谁定。
> **本文不记具体数值** —— 数值以 `config/*.yaml` 与 `robot_config.h` 为准，
> 实测用 `ros2 topic hz <话题>`。

## 话题总览

「速率」列写的是这个话题跟着谁走，不是具体数字。

| 话题 | 类型 | 发布者 | 订阅者 | 速率跟谁 |
| --- | --- | --- | --- | --- |
| `/cmd_vel_keyboard` | `Twist` | 外部（teleop / app） | twist_mux | 外部 |
| `/cmd_vel_nav` | `Twist` | Nav2 | twist_mux | Nav2 `controller_frequency` |
| `/diff_cont/cmd_vel_unstamped` | `Twist` | twist_mux | diff_cont | 上游最快的那路 |
| `/joint_states` | `JointState` | joint_broad | robot_state_publisher | **主链路同频** |
| `/imu_broad/imu` | `Imu` | imu_broad | **ekf_filter_node** | **主链路同频** |
| `/diff_cont/odom` | `Odometry` | diff_cont | odom_relay | **主链路同频** |
| `/odom` | `Odometry` | odom_relay | ekf_filter_node | **主链路同频** |
| **`/odometry/filtered`** | `Odometry` | ekf_filter_node | slam_toolbox / Nav2 | **主链路同频** |
| `/scan` | `LaserScan` | sllidar_node | laser_filter | 雷达硬件扫描速率 |
| **`/scan_filtered`** | `LaserScan` | laser_filter | slam_toolbox / Nav2 | 同 `/scan` |
| `/tf` (`odom→base_footprint`) | `TFMessage` | **ekf_filter_node** | 全局 | **主链路同频** |
| `/tf` (`map→odom`) | `TFMessage` | slam_toolbox | 全局 | slam `transform_publish_period` |
| `/tf_static` | `TFMessage` | robot_state_publisher | 全局 | latched |
| `/robot_description` | `String` | robot_state_publisher | ros2_control_node | latched |
| `/diagnostics` | `DiagnosticArray` | ros2_control_node | — | — |

## 速度指令流

```
键盘/app 遥控          Nav2
      │                  │
/cmd_vel_keyboard   /cmd_vel_nav
    (优先级高)         (优先级低)
      └────────┬─────────┘
            twist_mux          ← 优先级仲裁；超过 cmd_vel_timeout 无指令自动停
               │
   /diff_cont/cmd_vel_unstamped
               │
           diff_cont           ← diff_drive_controller
               │
   Stm32SerialHardware::write()
               │
   /dev/ttyS7 @115200 → STM32F303
   0x01 帧 [vx, 0, vyaw]（int16 ×1000，大端）
```

**速度限制**（`config/hw_controllers.yaml`）：线速度 `-0.3 ~ +0.4 m/s`（加速度 ≤1.5 m/s²）、
角速度 `±1.2 rad/s`（加速度 ≤2.0 rad/s²）。

> 底盘物理上限 = `WHEEL_MAX_RAD_S (27.2) × 有效轮半径`，有效半径 = `wheel_radius × radius_multiplier`
> （都在 `hw_controllers.yaml`，随标定变）。ROS 侧刻意限得更保守。
> **这里不再记具体数值** —— 它是派生量，写死必然过期（2026-08-13 前这里写的 0.885 就是错的：
> 既沿用了作废的固件 `WHEEL_RADIUS`，又没算 multiplier）。

## 里程计流

```
STM32F303  ← 控制环（robot_config.h 的 CONTROL_FREQ_HZ）
   │ 0x0A 帧 [vx_mm/s, vyaw_mrad/s, yaw_cdeg]（int16 大端）
   │
Stm32SerialHardware::read()          ← 超时后跳过本周期，不阻塞
   │ 解算 v_left/right = (vx ± vyaw·L/2) / R
   │
diff_cont（diff_drive_controller）    ← enable_odom_tf: FALSE，不发 TF
   │
/diff_cont/odom  ──odom_relay──→  /odom
                                     │
imu_broad → /imu_broad/imu ──────────┤
                                     ▼
                            ekf_filter_node（全链路同频）
                                     │
                    /odometry/filtered + TF odom→base_footprint
                                     │
                            slam_toolbox / Nav2
```

> ⚠️ **TF 只有 EKF 发。** `hw_controllers.yaml` 的 `enable_odom_tf` 关着，
> `ekf_hw.yaml` 的 `publish_tf` 开着。两处都发会打架。
>
> ⚠️ **EKF 吃的是 `/imu_broad/imu`，不是 `/imu/data`。**
> `ekf_hw.yaml` 里那行 `# imu0: /imu/data`（走 `imu_complementary_filter`）**是注释掉的**。
>
> `odom_relay` 是必需的：`diff_drive_controller` 固定发 `/diff_cont/odom`，而 EKF 订阅 `/odom`。

**关键几何**：`hw_controllers.yaml` 的 `wheel_separation` / `wheel_radius` 是里程计几何的
唯一真相源（固件那两个宏是死代码）。2026-08 底盘重做后实测过一轮，三个 multiplier 已复位、
待重新标定 —— 标定前别信它们。

## TF 树

```
map                       ← slam_toolbox（周期见 mapper_params_hw.yaml 的 transform_publish_period）
 └── odom                 ← ekf_filter_node（全链路同频）
      └── base_footprint
           └── base_link                    ← robot_state_publisher（静态）
                └── chassis
                     ├── laser_frame        （静态，雷达外参）
                     ├── caster_front/back_wheel
                     ├── left_wheel         （随 /joint_states）
                     └── right_wheel        （随 /joint_states）
```

> `view_frames` 里静态 TF 显示 `rate: 10000` 属正常（latched，与频率无关）。

## 频率一览

**下表只记「哪个环节的频率由哪个键定」，不记数值** —— 数值改了这里不会跟着改，
去指到的文件里取当前值。

**最重要的关系：STM32 控制环、controller_manager、EKF 三者必须同频**，这是刻意对齐的，
改一个就要改另两个。

| 环节 | 参数 | 去哪看 |
| --- | --- | --- |
| STM32 控制环 | `CONTROL_FREQ_HZ` | `firmware/.../robot_config.h` ┐ |
| `controller_manager` | `update_rate` | `hw_controllers.yaml`　　　　 ├ 这三个必须相等 |
| `ekf_filter_node` | `frequency` | `ekf_hw.yaml`　　　　　　　　┘ |
| `diff_cont` 发里程计 | `publish_rate` | `hw_controllers.yaml` |
| `sllidar_node` | — | 思岚 C1 标准扫描模式定死，不可调 |
| `slam_toolbox` 发 TF | `transform_publish_period`（周期，不是频率） | `mapper_params_hw.yaml` |
| Nav2 `controller_server` | `controller_frequency` | `my_bot_nav/config/hw/nav2_params_hw_*.yaml` |
| Nav2 `planner_server` | `expected_planner_frequency` | 同上 |
| Nav2 costmap | `update_frequency` / `publish_frequency`（local 与 global 各一份） | 同上 |
| Nav2 `behavior_server` | `cycle_frequency` | 同上 |
| 行为树 | `bt_loop_duration`（毫秒周期，不是频率） | 同上 |

### 超时阈值

| 参数 | 含义 | 去哪看 |
| --- | --- | --- |
| `sensor_timeout` | 传感器静默超此值，EKF 丢弃该源。必须 ≥ 2×(1/传感器频率) | `ekf_hw.yaml` |
| `cmd_vel_timeout` | 无指令则 diff_cont 停车 | `hw_controllers.yaml` |
| 串口 read 超时 | 超时则本周期跳过，不阻塞 | `stm32_serial_hw.cpp` |
| slam `transform_timeout` | TF 查询超时 | `mapper_params_hw.yaml` |

### 关键约束

| 约束 | 怎么核对 |
| --- | --- |
| `sensor_timeout ≥ 2 × (1/传感器频率)` | `ekf_hw.yaml` 的 `sensor_timeout` 对 `ros2 topic hz /imu_broad/imu` 实测周期，留数倍余量 |
| EKF 频率 ≥ 最快传感器频率 | `ekf_hw.yaml` 的 `frequency` 对 `/odom` 与 `/imu_broad/imu` 的实测频率 |
| STM32 与 controller_manager 同频 | `robot_config.h` 的 `CONTROL_FREQ_HZ` 对 `hw_controllers.yaml` 的 `update_rate` |

## 节点启动顺序

用 `TimerAction` 分级延迟 —— spawner 必须等 `controller_manager` 的服务就绪。

| 顺序 | 节点 |
| --- | --- |
| 立即 | `robot_state_publisher`、`ros2_control_node`（打开 `/dev/ttyS7`）、`sllidar_node`、`laser_filter`、`twist_mux`、`odom_relay` |
| 延迟① | spawner `joint_broad` |
| 延迟② | spawner `imu_broad` |
| 延迟③ | spawner `diff_cont` |
| **延迟④** | `ekf_filter_node`（**必须等 `imu_broad` 就绪**，这是顺序不能乱的原因） |

> 四级延迟的秒数在 `robot_bringup.launch.py` 的 `TimerAction` 里。
> 起完 launch 别立刻发指令 —— 等到最后一级过去。
