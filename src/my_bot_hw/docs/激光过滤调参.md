# 激光雷达过滤器调试指南

> 配置文件：`config/laser_filters.yaml`
> 过滤链：`/scan`（原始）→ **laser_filter_node** → `/scan_filtered`（干净）
> SLAM / Nav2 均订阅 `/scan_filtered`

---

## 一、整体过滤链与顺序

```
/scan (原始)
  │
  ├─ [1] LaserScanRangeFilter          距离范围裁剪（去盲区 + 去远点）
  ├─ [2] ScanShadowsFilter             掠射伪点 / 拖尾点
  ├─ [3] LaserScanSpeckleFilter        斑点过滤（去孤立噪点）
  └─ [4] StaticLaserScanPolygonFilter  车体外廓内的点（自遮挡、立柱回波）
  │
/scan_filtered (干净)
```

**顺序有语义，不可换**：
- 先距离裁剪再做邻域判断，避免无效远点被当成"邻居"干扰窗口计算。
- **shadow 必须在 speckle 之前**：拖尾点是**连成串**的，speckle 的邻域窗口判据结构性抓不到它
  —— 这也是为什么单纯收紧 speckle 阈值治不了拖尾。
- polygon 放最后：它按几何删点，不依赖邻域，放哪都对，但放最后可以少算几百个点。

> **本页所有阈值都来自实测**，出处：`docs/spec/2026-08-14-2D激光链路优化.md` 阶段 A
> （2026-08-14，601 帧静止采集）。
> ⚠ 「相邻点」类阈值（shadow 角、speckle 距离差）与**角分辨率强绑定**。
> 本机 `/scan` = 720 束/圈 = **0.501°/束**、10.02 Hz。改了 `scan_mode` / `angle_compensate`
> 必须重跑 `ros2 run my_bot_hw lidar_diag.py noise <采集.npz>` 重取分位数，不要沿用。

## 二、LaserScanRangeFilter（距离范围过滤）

### 作用
将距离不在 `[lower_threshold, upper_threshold]` 范围内的点替换为 `±inf`，SLAM 和 Nav2 自动忽略 `inf` 值。

### 参数说明

| 参数 | 当前值 | 含义 |
|------|--------|------|
| `lower_threshold` | `0.10` | 最小有效距离（米）。低于此值视为盲区噪点 |
| `upper_threshold` | `5.0` | 最大有效距离（米）。高于此值视为无效远点 |
| `lower_replacement_value` | `-.inf` | 近点替换值（`-.inf` = 清除） |
| `upper_replacement_value` | `.inf` | 远点替换值（`.inf` = 清除） |
| `use_message_range_limits` | `false` | 是否使用消息头里的 range_min/max，设为 false 用上方手动值 |

### 调大 / 调小的物理效果

| 参数 | 调大 | 调小 |
|------|------|------|
| `lower_threshold` | 去掉更多近点，机器人周围空白区变大，可能丢失近处障碍物 | 保留更多近点，盲区噪点可能污染 costmap |
| `upper_threshold` | 保留更远的点，建图范围更大，但远处噪点也更多 | 只使用可靠近距离，建图更干净但看不到远处墙 |

### 调试方法
1. 启动机器人，打开 RViz，添加 LaserScan 分别显示 `/scan` 和 `/scan_filtered`
2. 将机器人放在已知 0.08m 的近物旁，观察 `/scan` 的近点是否被 `/scan_filtered` 过滤
3. `lower_threshold` 设置原则：**比 C1 盲区上边界（约 0.08m）多留 0.02m 安全余量 = 0.10m**

```bash
# 查看当前 scan 的距离范围
ros2 topic echo /scan --field range_min --once   # C1 输出约 0.08
ros2 topic echo /scan --field range_max --once   # C1 输出约 12.0
```

## 三、ScanShadowsFilter（掠射伪点 / 拖尾点）

### 作用
删除**掠射角伪点**：光束几乎平行于物体表面时，回波被拉长成一串"拖"在真实表面后面的假点。
典型出现在门框、桌腿、墙角这类边缘的**背侧**。

它和 speckle 的分工是结构性的：拖尾点**连成串**（不孤立），speckle 的邻域窗口判据抓不到；
反过来单点跳变 shadow 也不管。两个都要，且顺序不能换。

### 参数说明

| 参数 | 当前值 | 含义 |
|------|--------|------|
| `min_angle` | `18` | 度，`[0,90]`。相邻两点连线与视线夹角小于此值 = 掠射 |
| `max_angle` | `162` | 度，`[90,180]`。= `180 − min_angle`，另一侧的对称门限 |
| `window` | `1` | 只与紧邻点比。0.5°/束下拖尾串很短，放大只会误伤 |
| `neighbors` | `1` | 命中后向外删 1 个**更远的**邻点 |
| `remove_shadow_start_point` | `false` | 是否连触发点本身一起删 |

判据与 `lidar_diag.py noise` 完全同式：`angle = atan2(r2·sin Δθ, r1 − r2·cos Δθ)`。
**18° 的出处**：A1 实测该角的 1% 分位 = 18.55°（0.5% 分位 17.20°，中位 89.75°）——
只砍最掠射的那一小撮。

### 两个坑

- **`neighbors: 0` 会让整个滤波器空转。** 源码里删除循环是
  `for index in [i-neighbors, i+neighbors]: if ranges[i] < ranges[index]`，
  `neighbors=0` 时退化成自己和自己比，永远不成立。
- **`remove_shadow_start_point: true` 会删真实边缘点。** 触发点常常就是门框/桌腿的
  真实边缘；现配置只删"更远的那个"，而拖尾点总是拖在真实表面**后面**，正好是它。

### 调大 / 调小的物理效果

| 参数 | 调大 | 调小 |
|------|------|------|
| `min_angle` | 砍得更狠，拖尾更干净，但开始吃真实的斜墙/斜面点 | 更保守，拖尾残留 |
| `neighbors` | 一次命中删更多后续点，长拖尾清得更净，误伤风险上升 | 只清紧邻，长拖尾会剩尾巴 |

## 四、LaserScanSpeckleFilter（斑点过滤器）

### 作用
检测并删除"孤立点"——与周围点距离差异过大的单个或少数点。典型场景：玻璃反射点、粉尘颗粒、电缆截面点。

### 参数说明

| 参数 | 当前值 | 含义 |
|------|--------|------|
| `filter_type` | `0` | `0` = DISTANCE 模式（距离差判断），`1` = EUCLIDEAN 模式（欧式聚类） |
| `max_range` | `8.0` | 仅对此距离以内的点做斑点检测（米）。远处点不参与，节省计算 |
| `max_range_difference` | `0.24` | 窗口内相邻点的最大允许距离差（米）。超过此值视为斑点 |
| `filter_window` | `2` | 检测窗口半径（检查前后各 2 个点，共 5 点窗口）|

> **0.24 的出处**：A1 实测相邻点跳变的 99.5% 分位 = 0.236 m（99% 分位 0.093）。
> 2026-08-14 之前这里长期是 `0.6`（接近空转），而本文档记的是 `0.1`（从未生效过）——
> 两个数都是拍的，现在换成实测分位数。

### filter_type 选择

| 模式 | 适用场景 | 特点 |
|------|---------|------|
| `0` (DISTANCE) | 普通室内环境，障碍物边缘清晰 | 速度快，参数直观（距离差阈值） |
| `1` (EUCLIDEAN) | 障碍物形状复杂、大量孤立点 | 效果更强，计算量稍大 |

### 调大 / 调小的物理效果

| 参数 | 调大 | 调小 |
|------|------|------|
| `max_range` | 对更远处的点也做斑点检测，过滤更彻底 | 只过滤近处，远处噪点保留 |
| `max_range_difference` | 允许更大距离跳变才算斑点，过滤更宽松 | 更灵敏，容易误删障碍物边缘点 |
| `filter_window` | 窗口更大，判断更稳健，但可能连带删除正常点 | 窗口更小，只检测紧邻点，误删少 |

### 调试方法
**别再靠"逐步减小看效果"来定这个数** —— 那正是它一度变成 0.6、文档写成 0.1 的原因。
正确做法是量一遍本机的相邻点跳变分布，取分位数：

```bash
ros2 run my_bot_hw lidar_diag.py record --duration 60 --out ~/lidar_diag/noise.npz   # 车静止
ros2 run my_bot_hw lidar_diag.py noise ~/lidar_diag/noise.npz
```

取 **99.5% 分位**：意思是"正常环境下每 200 个相邻点对才会自然出现一次这么大的跳变"，
比它更大的基本就是噪点。取太小（< 99% 分位）会开始吃薄门框、桌腿的真实边缘。

```bash
# 对比过滤前后点数（差值越大说明过滤效果越明显）
ros2 topic echo /scan          --once | python3 -c "import sys; d=sys.stdin.read(); print('raw nan:', d.count('nan'))"
ros2 topic echo /scan_filtered --once | python3 -c "import sys; d=sys.stdin.read(); print('filtered nan:', d.count('nan'))"
```

## 五、StaticLaserScanPolygonFilter（车体自遮挡）

### 作用
把落在**车体外廓多边形内**的点全部设为 `nan`。治的是车体自身、四根立柱、线缆造成的
"贴身假障碍" —— 它们在 costmap 里会变成永远甩不掉的近距障碍。

**为什么不用角度扇区**（2026-08-14 换掉了原来的 `AngularBoundsFilterInPlace` 占位）：
车体是不规则多边形，且 **`base_link` 不在圆盘圆心**（盘心在其后方 0.047 m）。
用角度扇区要手工标多段，且雷达外参一改全部作废；多边形是按几何算的，改外参自动跟随。

**Static 变体**：只在第一帧把多边形转进 `laser_frame` 并缓存，之后逐点比对，
省掉每帧 720 点的 TF 变换。代价是**改了雷达外参必须重启节点**才会重新取 TF。

### 参数说明

| 参数 | 当前值 | 含义 |
|------|--------|------|
| `polygon_frame` | `base_link` | 多边形所在坐标系 |
| `polygon` | 10 点裸外廓 | 车体真实外廓，**无余量** |
| `polygon_padding` | `0.02` | 米，向外扩的余量 |
| `invert` | `false` | `false` = 删多边形**内**的点 |

### 三个坑

- **`invert: true` 会清空整帧。** `false` 删内部（要的），`true` 删外部（只剩车体）。
- **`polygon` 填裸外廓，不要填"外廓 + 余量"的成品数。** 裸外廓与
  `my_bot/description/robot_core.xacro` 和 nav2 各参数文件注释里的那份是**同一个值**；
  余量交给 `polygon_padding`，否则仓库里会多出一份会走样的真相。
- **`padPolygon` 是按坐标轴符号加余量**（`pt.x += sign(x)·pad`，y 同理），
  不是法向等距外扩 ⇒ 四个主轴方向正好 20 mm，斜向约 28 mm。偏差在"多删一点"这一侧。

### 外廓的出处

```
圆盘    以 (-0.047, 0) 为心、r = 0.11          ← robot_core.xacro 的 base_link visual
驱动轮  俯视矩形 x∈[-0.035, 0.035]、|y|∈[0.082, 0.11]
        （轮心 y = 0.096、轮 r = 0.035、厚 0.028）
```

⚠ **轮子必须单独算进来**：圆盘在 x=0 处的半宽只有 √(0.11²−0.047²) = 0.0995，
而轮外沿在 0.11 —— 轮子在此突出盘缘 10.5 mm。改这个多边形时务必把轮子四角一起验。

### 验证它没误伤

在车体多边形**之外** 0.09~0.15 m 处放一个纸盒，它必须在 `/scan_filtered` 里**仍然可见**。
只验"贴身假障碍没了"是不够的 —— 那个用 `lower_threshold` 一刀切也能做到，代价是把
真实近距障碍一起砍掉。

## 附、已删除的角度扇区法（保留说明以防有人想加回来）

原 `AngularBoundsFilterInPlace` 是个 `lower_angle == upper_angle == 0.0` 的**空占位**，
从未生效过，2026-08-14 由上面的多边形滤波器取代。

立柱阴影的四段扇区过滤（spec 的 B3b）判为**无收益、不做**：四根 ⌀6 mm 立柱合计只挡
13.41° 视野，且阴影区内的束会直接返回柱面距离（已由多边形滤波器删净），扇区过滤只剩
"边缘掠射伪点"这一点收益，而 A0 的反证栏显示边缘本就干净。

真要加回来，两件事不能错：用 **InPlace** 变体（非 InPlace 会改变点数组长度、破坏角度映射），
以及角度填的是 **`laser_frame` 角度**而不是 `base_link` 角度（本机 `lidar_yaw ≈ π`，两者差 180°）。

### 附录：不要靠"扫一遍找近点"去定位遮挡物

老办法是订阅 `/scan`、把所有 `0.05 < r < 0.25` 的束打印出来当作遮挡。
**2026-08-14 实测这个办法在真实环境里会骗人**：它捞出 8 个低反射率的环境物体当立柱，
而真正的立柱因为回波间歇（柱面 99.5 mm 落在 C1 探测能力边缘，命中率只有约 17%）反被筛掉。

尺寸已知就不该盲找。用 `lidar_diag.py verify` 按 CAD 尺寸**核对**：

```bash
ros2 run my_bot_hw lidar_diag.py record --duration 60 --out ~/lidar_diag/a0.npz   # 车静止
ros2 run my_bot_hw lidar_diag.py verify ~/lidar_diag/a0.npz
```

它回答的是"这几个**算出来的**位置上实测到了什么"，方位不对会直接报错 —— 能被证伪。

## 六、整体调试流程

```
Step 1  先只启用 RangeFilter，验证近点/远点裁剪效果
        → ros2 topic hz /scan_filtered 确认话题存在
        → RViz 对比 /scan 和 /scan_filtered

Step 2  采一份 60s 静止数据，跑 lidar_diag.py noise
        → shadow 角 1% 分位 → ScanShadowsFilter 的 min_angle
        → 跳变 99.5% 分位   → SpeckleFilter 的 max_range_difference
        两个数一起回填，不要靠"看着调"

Step 3  跑 lidar_diag.py verify 核对车体/立柱的贴身回波是否已被多边形删净
        → 别忘了在多边形外放个纸盒验"没误伤"

Step 4  跑一圈建图，对比加滤波前后的地图质量
        → 墙体线条是否更连续，孤立障碍物标记是否减少
        → ⚠ 墙的**厚度/重影**不归滤波管，那是运动畸变，见 spec 的 C 阶段
```
