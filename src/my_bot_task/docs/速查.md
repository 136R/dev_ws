# my_bot_task 速查

## 起

```bash
# 仿真全链路（多房间世界）
ros2 launch my_bot launch_sim.launch.py \
  world:=$HOME/dev_ws/src/my_bot/worlds/home_4rooms.sdf
ros2 launch my_bot_slam slam.launch.py use_sim_time:=true mode:=localization
ros2 launch my_bot_task task.launch.py use_sim_time:=true   # 内含 Nav2 + keepout

# 实机（先在仿真验收通过）
ros2 launch my_bot_hw robot_bringup.launch.py
ros2 launch my_bot_slam slam.launch.py mode:=localization
ros2 launch my_bot_task task.launch.py
```

`task.launch.py` 参数：`use_sim_time`(false) / `controller`(neupan) / `map`("") / `params_file`。

## 看

```bash
ros2 topic echo /task/status                    # latched，一订阅就有
ros2 topic echo /task/nav_status                # 喂给 app 的按钮：2=EXECUTING(按钮显示) 4=SUCCEEDED
ros2 topic info /goal_pose --verbose            # ⚠️ 订阅者只能有 task_manager
```

## app 侧：两个端口，但你只开 8080

```
浏览器打开 http://<ip>:8080          ← 网页本身（C++ 后端 ros_gui_backend，原样未动）
   └─ 网页 JS 每秒后台 fetch :8090   ← 只为拿任务卡的数据（本包自开的口）
```

**`:8090` 不用手动开，也不是"改了端口"。** 任务层没起 / 8090 不通 → 网页照常用，
只是底部任务卡不显示（静默降级，不报错）。

`gui_app_settings.json` **不需要为任务层改任何字段**。

## 戳

```bash
# 召唤（等价于 app 上点一下拓扑点 / RViz 里点 2D Goal Pose）
ros2 topic pub --once /goal_pose geometry_msgs/msg/PoseStamped \
  "{header: {frame_id: 'map'}, pose: {position: {x: -2.8, y: 2.2}, orientation: {w: 1.0}}}"

# 「我倒完了，回去吧」（等价于 app 上点「停止导航」）
ros2 topic pub --once /goal_pose/cancel std_msgs/msg/Empty "{}"

# 清空队列
ros2 topic pub --once /task/cancel_all std_msgs/msg/Empty "{}"
```

## 调

```bash
# 等待时长临时改短（调试用；最终验收要用 120s 真跑一遍）
ros2 launch my_bot_task task.launch.py use_sim_time:=true \
  params_file:=/dev/null --ros-args -p dwell_sec:=10.0

# 绕开任务层直接指挥 Nav2（用来区分"门太窄"还是"任务层有 bug"）
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: 'map'}, pose: {position: {x: -2.8, y: 2.2}, orientation: {w: 1.0}}}}"
```

## home_4rooms 世界的房间中心（标点用）

```
北侧  (-2.8, 2.2)   (0.0, 2.2)   (2.8, 2.2)
南侧  (-2.8,-2.2)   (0.0,-2.2)   (2.8,-2.2)

```

## 症状 → 原因

| 症状 | 多半是 |
| --- | --- |
| app 上点了没反应 | app 设置页的 `NavGoalTopic` 被改过（默认要是 `/goal_pose`） |
| **改了 `task_params.yaml` 的 `dwell_sec` 却不生效** | `task_params_file:=` 指到了不存在的文件 → **launch_ros 静默忽略整个 yaml**，全用代码默认值。用 `ros2 param get /task_manager dwell_sec` 一对就知道 |
| app 上的任务卡一直不出现 | ① `my_bot_task` 没起；② `:8090` 不通（`curl localhost:8090/task/status` 试）；③ 待命(IDLE)时本来就整张隐藏，先召唤一个房间再看 |
| 召唤某个房间总是去到别的房间 | 两个导航点重名了（会互相覆盖）。看 task_manager 的 error 日志 |
| 「约 N 秒」估得离谱 | 调 `eta_speed_mps`。旁边的「还有 N 米」是 Nav2 给的**真实**路径长度 —— 距离对而时间不对，就是这个速度值没调准 |
| 跑过去了但不等待、不归位 | remap 没生效 —— `ros2 topic info /goal_pose --verbose` 看看有没有 bt_navigator |
| "等 2 分钟"实际不是 2 分钟 | 忘了传 `use_sim_time:=true` |
| 日志说"读不到 .topology" | 还没在 app 上标点；标完保存，1~2s 自动热载 |
| 不肯归位，warn 说没有待命点 | 拓扑里没有名叫 `HOME` 的点 |
